# 项目类型与真实工作流

## 1. 咨询项目不是按公司名运行，而是按问题类型运行

MBB、罗兰贝格和四大都可能跨行业承担多种项目。对经纬更有效的分类是“客户要做什么决定”。

## 2. 八类常见项目

### A. 企业/业务单元战略

**客户问题**：未来 3—5 年在哪里竞争、靠什么赢、资源如何分配？

**流程**：

1. 明确使命、业绩差距与决策范围；
2. 外部趋势和情景；
3. 业务组合与价值创造表现；
4. 市场吸引力和竞争地位；
5. 核心能力与差距；
6. 战略选项和财务影响；
7. 组合选择、资本配置和战略路线图。

**初级顾问工作**：市场和公司研究、竞争 benchmark、业务单元数据分析、管理层访谈、组合图、财务情景、PPT。

**交付物**：战略诊断、where-to-play/how-to-win 选择、组合策略、财务影响、路线图。

### B. 增长/市场进入

**客户问题**：是否进入某市场、服务哪类客户、采用什么进入方式？

**流程**：

1. 定义市场边界和进入目标；
2. 市场规模、增速和需求驱动；
3. 客户细分、需求和支付意愿；
4. 竞争、渠道、法规和进入壁垒；
5. 企业能力与合作/M&A 选择；
6. 收入、成本、投资和风险情景；
7. 进入方式、GTM 和阶段性试点。

**交付物**：market model、customer segments、entry options、business case、GTM roadmap。

### C. 产业链/行业战略

**客户问题**：一个产业如何演化，价值和权力在哪些环节，我们应占据什么位置？

**流程**：

1. 产业定义、细分和技术边界；
2. 需求、供给、政策和技术情景；
3. 价值链、利润池和关键控制点；
4. 企业/生态图谱和竞争格局；
5. 客户需求与商业模式；
6. 本企业/地区能力和缺口；
7. 进入、延链、合作、投资或退出选项；
8. 经济性、风险和实施。

**与原经纬关系**：这是原七层最接近的项目，但必须增加客户、利润池、能力、business case 和实施。

### D. 商业战略、定价和 GTM

**客户问题**：如何提高收入、定价、客户获取和渠道效率？

**流程**：客户和交易数据 → 分群/旅程 → 产品/价格/渠道表现 → 收入与利润泄漏 → 方案测试 → 销售/营销运营调整。

**常见分析**：客户生命周期价值、流失、价格弹性、产品组合、渠道成本、销售漏斗、营销 ROI。

**交付物**：客户策略、价格架构、渠道方案、销售举措、收入提升 business case。

### E. 商业尽调 / 交易策略

**客户问题**：是否投资/收购，这项资产的增长质量、竞争位置和主要风险是什么？

**流程**：

1. 建立投资假设和红旗清单；
2. 市场、客户、竞争和监管研究；
3. 管理层资料和数据请求；
4. 市场模型、客户留存和份额分析；
5. 收入增长可持续性、协同和风险；
6. downside/base/upside 情景；
7. 投资结论、关键条件和后续尽调问题。

**特点**：周期短、证据要求高、需要明确事实与假设边界。

### F. 运营模式与成本转型

**客户问题**：战略确定后，组织怎样工作才能降低成本、提升速度或质量？

**流程**：

1. 明确价值目标；
2. 现状流程、组织、成本、服务和治理诊断；
3. benchmark 和痛点根因；
4. 目标能力、流程、组织、技术和治理设计；
5. 成本/价值 business case；
6. 过渡方案、举措、责任与风险；
7. 实施和绩效跟踪。

**交付物**：as-is / to-be process、capability map、target operating model、org/governance、cost case、roadmap。

### G. 数字化/技术转型

**客户问题**：技术和数据应如何帮助业务增长或提效，优先投什么、如何组织和实施？

数字化转型不是“做一份数字趋势报告”，也不等于直接写系统代码。策略与转型顾问通常连接业务目标与后续技术实施。

#### 完整流程

1. **业务价值定义**
   - 客户增长、成本、速度、风险或体验目标；
   - 技术投资必须对应业务 KPI。

2. **外部与行业扫描**
   - 竞争者数字能力、技术趋势、客户预期、监管；
   - 判断哪些变化真正影响本行业。

3. **现状诊断**
   - 客户旅程与业务流程；
   - 数据质量、系统和架构；
   - 组织、人才、治理和供应商；
   - 成熟度评分和痛点根因。

4. **机会与用例池**
   - 列出数字产品、自动化、数据/AI、平台或系统用例；
   - 明确用户、痛点、流程节点、数据和预期价值。

5. **优先级与试点**
   - 价值、可行性、风险、依赖和实施时间评分；
   - 选择 quick wins、基础能力和战略举措；
   - 必要时做原型和用户测试。

6. **目标状态设计**
   - future customer journey / process；
   - target operating model；
   - 能力、角色、治理、数据和高层架构；
   - 业务与功能需求。

7. **Business case**
   - 收益、成本、资源、风险、情景和回收周期；
   - 明确哪些价值是可量化、间接或尚待验证。

8. **Roadmap 与治理**
   - 分波次项目组合；
   - 依赖、里程碑、负责人、预算和决策门；
   - transformation office / PMO 机制。

9. **实施支持**
   - 需求细化、系统/供应商选择、user story、UAT；
   - 风险和问题管理；
   - change impact、沟通、培训和 adoption；
   - benefit tracking。

#### 初级顾问会实际制作的材料

- stakeholder interview guide 与纪要；
- competitor digital benchmark；
- customer journey / process map；
- digital maturity heatmap；
- pain point 与 capability gap；
- use-case inventory 和优先级矩阵；
- business requirements / user stories；
- Excel business case；
- target operating model；
- transformation roadmap；
- weekly PMO / SteerCo deck；
- change impact 和 training/communication plan。

### H. 区域、园区与地产策略

**客户问题**：一个区域或物业应承载什么功能、服务谁、如何布局和运营？

**流程**：

1. 项目决策与空间边界；
2. 区域/市场/产业/政策背景；
3. 客群、需求、旅程和使用场景；
4. 竞品、案例与供需；
5. 区位、交通、空间、设施和项目能力；
6. 定位、功能、业态/产业组合选项；
7. 面积/容量/财务/运营可行性；
8. 空间落位、招商/运营和实施路线图。

这是经纬最有历史证据的模板，也是与其他战略项目连接的起点。

## 3. 八类项目真正共享的工作

```text
客户问题与决策
  → 问题树 / 假设 / workplan
  → desk research + 客户数据 + 访谈
  → 结构化分析 / benchmark / 模型
  → 事实、洞察与反证
  → 选项 + business case + 风险
  → 管理层材料 / workshop / decision log
  → roadmap / owner / KPI / implementation tracking
```

共享的是这条工作链，不是固定的产业七层。不同项目只替换中间的分析组件。

## 4. 地产产业策略与数字化转型的交集和差异

| 环节 | 地产/产业策略 | 数字化转型 | 经共享能力 |
|---|---|---|---|
| 决策 | 定位、产业/业态、空间和运营 | 技术投资、用例、流程和运营模式 | brief、问题树、决策日志 |
| 外部证据 | 政策、产业、区位、竞品、案例 | 技术、竞争者、客户预期、监管 | research、source ledger |
| 内部证据 | 土地/物业、客流、面积、招商能力 | 流程、系统、数据、组织、人才 | data room、interview、benchmark |
| 分析 | 空间、供需、价值链、场景 | journey、process、maturity、architecture | analysis notebook、QA |
| 选项 | 定位/功能/业态/产业组合 | use cases、target state、sourcing/system options | option matrix、scoring |
| 经济性 | 面积、租金、投资、运营 | 收益、成本、资源、回收期 | business case engine |
| 实施 | 招商、运营、建设、阶段开发 | roadmap、PMO、UAT、change | initiative tracker、benefit tracking |
| 表达 | 规划/策划方案和铺位表 | transformation deck 和 SteerCo | deck、memo、workshop |

所以扩展到数字化不会使经纬偏离原方向；前提是保留同一套决策、证据、分析、选项、商业案例和实施对象，而不是新加一个“数字化报告生成器”。
