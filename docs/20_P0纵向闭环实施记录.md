# P0 纵向闭环实施记录

> 日期：2026-08-16（P0 收口附记 2026-08-19）  
> 产品基线：[PRD v0.5](01_PRD_v0.5.md)  
> 技术基线：[P0 最小技术架构与扩展接缝](19_P0最小技术架构与扩展接缝.md)  
> 当前里程碑：P0 已由产品所有者于 2026-08-19 收口。默认界面仍是一块工作台（本轮问题进度 + 给经理的稿 + 材料匣）。模型写一节仍先写入候选，人点「收下」才进稿。审查两栏停止加功能。docs/22 真人走查由产品所有者跳过，结果仍空。P1 第一刀拆问题、第二刀轮次归档与靠材料写稿已写入。现场缺陷见第 6 节。

## 1. 已实现

- Python 3.11+ 单体应用骨架；
- SQLite schema v0.1 引导，以及显式、幂等的 0.1→0.2、0.2→0.3、0.3→0.4、0.4→0.5、0.5→0.6 迁移；
- Project、Brief、ResearchQuestion、Source、EvidenceExcerpt、Claim、Finding、Option、DeliverableBlock、ReviewDecision 和 OverrideDecision 的规范化表；
- DeliverableBlock 与 Claim / Finding / Option 的显式关系表；
- `ProjectTemplate`、`AnalysisModule`、`SourceAdapter`、`WebSearchAdapter`、`Parser`、`ExecutionStrategy`、`DeliverableExporter` 和 `ViewProjection` 接口接缝（无第二业务实现）；
- P-001模板配置和对象样本导入；DB-001 至 DB-004 含实际正文；
- 报告优先投影与段落审查上下文投影；
- 本地命令行入口，用于迁移、导入、新建题目、列出题目、人工新增段落、挂接主张、更新主张核验、挂接判断、挂接方向、保存改稿候选、采用候选、查看报告、审查上下文、影响预览、段落评审和带风险推进；
- 只读本地 HTTP API：`GET /projects/{id}/report`、`GET /deliverable-blocks/{id}/review-context` 与 `GET /sources/{id}/impact-preview`，复用同一套投影；
- 报告优先网页（内部稿 + 审查侧栏）由同一进程提供，浏览器请求上述 API，不复制业务状态；
- 本地文件捕获：受控副本、SHA-256、新 Source 与 `supersedes_source_id`，不覆盖旧来源；
- 临时 ImpactPreview：沿显式 Source → Claim → DeliverableBlock 计算，存在 Finding/Option 显式关系时再传播；`GET /sources/{id}/impact-preview` 与报告页 `?impact=` 只读提示；不持久化、不改写内部稿；
- 段落评审与带风险推进：`POST /deliverable-blocks/{id}/review-decisions`、`POST /deliverable-blocks/{id}/override-decisions`、项目级 `POST /projects/{id}/override-decisions`；审查侧栏立即显示记录已创建、作用于哪个版本、本版如何处理、证据状态未改变；
- 段落版本保护：`deliverable_block_revisions` 保存当前快照与候选版本；评审/覆盖不自动改写 `current_text`；`POST .../revisions` 保存人工改稿候选，只有 `POST .../revisions/adopt` 在用户确认后替换当前稿，且仍不改变 Claim 核验状态；
- Markdown 导出：`POST /projects/{id}/exports/markdown` 读取本版纳入的当前内部稿，不重新生成事实、不改变核验状态；从本版排除的段落不进入正文；未采用候选不导出；
- Word 导出：`POST /projects/{id}/exports/word` 读取同一批准投影，生成可编辑 .docx；不引入第三方包，不改 Markdown 语义，不改变核验状态；
- 评审或顶栏导出后，审查侧栏显示处理结果：已下载文件、本版纳入段数、核验与内部稿未改；失败也显示「没有完成」。不重新生成事实；
- 扩展接缝演练：`demo_market_scan` 模板配置与 `plain_text` 导出器已注册；不新增 schema、页面或第二业务实现；
- P-001纵向闭环能力基线对照：顺序走查内部稿、审查、补料、影响预览、局部重审、导出和重开恢复；记录见 docs/21；
- Brief / 本轮问题：从报告进入的任务边界投影与保存；读取同一 Brief / ResearchQuestion ID；不改写 Claim 核验状态或内部稿；
- 报告页补充材料：列出已有来源标题、保存本机文件为新 Source，并显示影响预览；不覆盖旧文件，不改写内部稿；来源编号跨题目全局分配；
- 空白题目创建：`POST /projects` 写入新 Project 与 Brief，并放入一条不含生成结论的占位内部稿；P-001模板会带上三条本轮问题，不从一句话生成判断；
- 空题目打开时可 `POST /projects/{id}/review-shell` 补同一条占位壳；已有段落时不改写；
- 题目删除：`DELETE /projects/{id}` 只删除该题对象与受控文件，不改写其他题目；任务边界可改题目名称；
- 人工新增段落：`POST /projects/{id}/deliverable-blocks` 写入新 DeliverableBlock 与 v1 快照；不含主张，不改写已有段落或其他题目，也不从一句话生成结论；
- 人工挂接主张：`POST /deliverable-blocks/{id}/claims` 写入 EvidenceExcerpt 与 Claim，并显式挂到当前段落；核验状态固定为已捕获，不改写内部稿，也不把客户提供标成已核实；
- 人工挂接判断：`POST /deliverable-blocks/{id}/findings` 写入 Finding，可选挂接本段主张与替代解释；不改写内部稿，也不改变主张核验状态；
- 人工挂接方向：`POST /deliverable-blocks/{id}/options` 写入 Option，默认状态为待验证；不改写内部稿，不改变主张核验状态，也不把方向写成推荐方案；
- 报告页题目列表与新建入口；无 `?project=` 时先选题，不再默认打开P-001样本；
- 报告页「新增段落」写入同一 DeliverableBlock 对象，保存后打开该段审查侧栏；
- 审查侧栏「挂接主张」读取同一 Source / Claim / DeliverableBlock，不自动解析文件；
- 审查侧栏「改本段正文」把改稿存为候选；确认采用后才替换当前内部稿，不改变主张核验状态；
- 现有两栏可操作壳：正文字号加大；中间拖动调整左右宽度并记住；审查侧栏主路径一次只打开「改这段 / 依据 / 过不过」中一块，总判断与方向收在「更多」；依据先点选再改核验。仍读取同一对象 ID，不是换皮或新工作区；
- 动作反馈：写入后侧栏顶部显示处理结果和下一步；失败也显示「没有完成」，不再静默；
- 挂接主张改为先点选来源再写摘录；按可访问 / 暂不可访问分组，不使用原生长下拉，也不做独立来源工作区；
- 可操作回退：核验可再改状态；评审再记新决定；改稿把上一版存为候选再采用；表单可取消点选 / 返回来源列表 / 取消挂接。不提供通用撤销，也不删除已挂主张；
- 人工推进主张核验：`POST /deliverable-blocks/{id}/claims/{claim_id}/verification` 只改 `Claim.verification_status`；界面主路径为「原文看过了 / 这轮先不用」，其余收入「其他情况」。不改写内部稿，不改独立核实标记，也不因评审/覆盖自动改核验；
- 网页候选先点选再打开或升为来源；收录后结果条提供「去打开链接」，打开后提供「去升为来源」。标题与备注先收起。未打开不得升为来源，也不得挂接主张；
- 补料后的影响预览给出「去补这句话的依据」：打开该段「依据」并点选刚保存的来源；已有依据时先收起表单。不自动抽取摘录，不改核验或内部稿；
- 核验或补依据后处理结果可进入「过不过」；先点选再确认，两种「从本版排除」分开标注；可以进本版或带风险推进后可导出。过不过仍不改变主张核验；
- 退回修改或记下改稿后，处理结果可「去用这版」；有未用的一版时优先显示。采用后才替换内部稿，核验不变；
- 总判断与方向收入「更多」，先点选再展开；记下总判断后可「去写方向」。不把方向写成推荐方案，不改核验或内部稿，也不由模型代写；
- 本轮任务先显示摘要，点「改任务边界」或点选一个问题再展开；保存后可「去补充材料」。新建题目只先填名称和情境，「补充本轮边界」才展开决策/交付/问题。不从一句话自动成稿；
- 挂接主张时摘录、主张和认识类型先出现，「补充口径与归属」才展开定位/口径/客户提供/宏观；挂接判断时观察和强度先出现，「补充依据」才展开支持主张和替代解释。新增段落后侧栏显示处理结果，可改这段或去补依据。不自动抽取，不改核验；
- 本机补料可在浏览器里选文件上传，写入新 Source 与受控副本；路径粘贴仍可用。不覆盖旧文件，不解析摘录；
- Windows 上 SQLite 连接确定性关闭，标准 `unittest discover` 可删除临时数据库。
- 本机命令 `demo-walk`：建空白题、改占位稿、补客户口头材料、挂依据、记下原文看过、批准进本版并导出 Word；不覆盖已有题目，不代写，客户口头不等于外部核实。PowerShell：`scripts\walk_blank.ps1`。
- 主路径人话：侧栏标题为「这一段」；导入样本用 `project.stage === internal_research_recovery` 标明不是模型刚写；空白题标明系统不会代写。改稿「换成这版」一次提出并采用，仍先有候选版本。看稿页不是产品首页。
- 大模型先拟：总判断/方向写入 `ModelSuggestion`；改这段写入既有改稿候选。未接密钥拒绝编造。人点「用这版」才进账本；不自动改 `current_text`，不改核验，不把模型记忆写成来源。
- 按本轮问题搜：人触发 `POST /projects/{id}/material-search`；默认公开网页搜索先打开主页再搜精简页，拦下再试一次，仍空才试 HTML 页；可选 Brave。本轮有候选后不再连搜下一条。检索词来自本轮问题，有模型密钥时可先拟检索词。只写入 `CandidateSource`；模型不得发明 URL；未打开不得升为 Source，不改核验，不改稿。拦截页不当成「没搜到」。工作台材料匣有「按这轮问题搜」。
- 「写这一节」发给模型的已挂原话会标明出处种类：只有 Claim 标成客户提供时才能写「据客户提供、口径待补」；公开网页和本机文件标成不是客户提供。不静默改写已收下的正文。

报告与审查侧栏读取同一个 DeliverableBlock ID；审查上下文通过显式关系回到 Claim、EvidenceExcerpt 和 Source，没有复制第二套结论。

## 2. 本轮没有实现

- 没有 PPT 导出或精装排版；
- 没有全文编辑器；可用审查侧栏「改本段正文」保存候选并确认采用，也可用「新增段落」写入新段落，仍不从一句话自动成稿；
- 没有从材料自动抽取摘录或主张；可用审查侧栏人工挂接主张、判断和待验证方向。
- 已有 `ModelSuggestion` 表与先拟/采用/放下动作；改这段可先拟一版改稿候选，写入既有 revision。本机设置 `JINGWEI_DRAFT_API_KEY` 后走 HTTP 先拟，可用 `JINGWEI_DRAFT_PROVIDER` 选 deepseek / openai 等。没密钥则拒绝编造。人点「用这版」才替换左边或挂判断/方向。没有 AnalysisArtifact 的完整持久化；
- 没有无人值守搜索 Agent；人触发「按这轮问题搜」只写入 CandidateSource。网页候选须人工打开后才升为 Source，未打开链接不得写成主张。
- 没有券商、机场业务模板，也没有第二业务页面；`demo_market_scan` 只是接缝演练配置；
- 没有完整工作台、问题拆解视图或 Agent。

## 3. 已验证不变量

1. schema 0.1 引导后迁移到 0.2，P-001样本导入成功；
2. 重复执行迁移不会重复修改 schema；
3. 从 0.1 数据迁移到 0.2 时，人工正文、来源哈希、评审和 Override 不丢失；
4. Claim 认识类型为 `factual_claim / inference / assumption / judgment`，不再接受 `hypothesis`；
5. Option 生命周期状态为 `candidate / needs_evidence / retained / deferred / excluded`，不再使用 `hypothesis`；
6. 报告投影返回 DB-001 至 DB-004 的实际正文；
7. DB-001 可追溯到客户提供的“60%+ 食品产业客群”及口径限制；
8. 报告投影与审查投影共享同一对象 ID；
9. 项目级与段落级 Override 均不改变 Claim 核验状态；
10. 重复导入同一项目会报错，不静默覆盖；
11. SQLite 外键关系生效；
12. 样本快照路径均为跨平台相对路径，且对应文件存在；
13. 使用后的测试数据库文件可以删除；
14. HTTP 报告与审查上下文返回与命令行投影相同的对象 ID 和正文；
15. 报告页不内嵌结论正文，由浏览器读取只读 API；审查侧栏与报告共用 DeliverableBlock ID；
16. 新材料创建新 Source 与受控副本，旧文件/哈希不被覆盖；Source ID 全局唯一，新题目不得复用已有 `S-001`；Parser 本切片不写入摘录；
17. ImpactPreview 只返回显式外键能够证明的主张、判断和段落；替代来源会并入被替代来源的显式链，但不改写 `DeliverableBlock.current_text`；
18. ReviewDecision 只作用于 DeliverableBlock；OverrideDecision 可项目级或段落级；二者都不改变 `Claim.verification_status`，也不自动覆盖当前内部稿；
19. 候选修订只有在用户确认采用后才成为 `current_text`；旧快照保留；
20. Markdown 导出只读取当前内部稿投影，不改变 `Claim.verification_status`，也不把未采用候选或已排除段落写入正文；
21. 注册 `demo_market_scan` 不增加迁移；注册 `plain_text` 导出器不改变 Markdown 导出；删除该模板配置后P-001项目仍可读取；
22. P-001样本可按「内部稿 → 审查 → 补料 → 影响预览 → 局部重审 → 导出 → 重开」顺序走通；替代文件中的数字不进入内部稿或导出；宏观来源不发明未关联段落；
23. Brief / 本轮问题与报告读取同一项目；更新任务边界不改变 `Claim.verification_status` 或 `DeliverableBlock.current_text`；空 id 可新增本轮问题，仍不改写内部稿；
24. Word 导出与 Markdown 读取同一批准投影；排除段落和未采用候选不进入 .docx；导出不改变核验状态，也不改变 Markdown 正文。导出接口附带处理结果：`record_kind=export`，核验与内部稿均未改。
25. 新建题目分配新 Project / Brief ID，并放入一条不含生成结论的占位内部稿；不覆盖已有项目；P-001样本主张核验状态与内部稿保持不变。已有段落时 `review-shell` 不改写。
26. 人工新增段落分配新 DeliverableBlock ID 与 v1 快照；不写入主张；不改写已有段落、其他题目或 `Claim.verification_status`。
27. 人工挂接主张写入新 EvidenceExcerpt / Claim，并显式关联当前段落；新主张核验状态为 `captured` 且 `independently_verified=false`；不改写 `current_text`，也不改变已有主张核验状态。客户提供不等于外部独立核实；宏观来源自动带上“不单独证明项目需求”。
28. 人工挂接判断写入新 Finding 并显式关联当前段落；可选支持主张与一条替代解释；不改写 `current_text`，也不改变 `Claim.verification_status`。审查侧栏与报告读取同一 Finding ID。
29. 人工挂接方向写入新 Option 并显式关联当前段落；默认 `candidate`；不改写 `current_text`，也不改变 `Claim.verification_status`。审查侧栏与报告读取同一 Option ID，不把方向写成推荐方案。
30. 人工改段落实成候选版本，不立刻替换 `current_text`；只有确认采用后才替换，旧快照保留，且不改变 `Claim.verification_status`。占位内部稿也走同一路径。
31. 人工更新主张核验只改该条 `Claim.verification_status`；不改写 `current_text`，不改 `independently_verified`，也不改其他主张。客户提供即使记为已交叉支持，仍不是外部独立核实。评审/覆盖仍不得改核验状态。
32. 报告页两栏壳不复制第二套结论；分栏宽度只存在浏览器本地，侧栏区块切换不改变对象 ID 或核验状态。
33. 审查侧栏动作无论成功或失败都投影处理结果；来源点选与主张点选不改变对象 ID。改稿回退只新增候选版本，不覆盖旧快照，也不改变 `Claim.verification_status`。
34. 网页候选只写入 CandidateSource；未打开不得升为 Source，也不得挂接主张。打开后升为新 Source，不覆盖旧来源，不解析摘录，不改变 `Claim.verification_status` 或内部稿。0.3 项目经显式迁移得到候选表，旧来源和主张不静默改写。界面先点选候选再打开或升为来源；收录与打开的处理结果带下一步，不自动搜索。
35. 浏览器补料可用 multipart 上传创建新 Source 与受控副本；空文件名或空内容被拒绝；上传与路径不能同时使用；不覆盖旧文件/哈希，不解析摘录，不改变 `Claim.verification_status` 或内部稿。路径粘贴仍可用于命令行。

- **一条观察，不是缺陷**：库里那段原话有个抽取时糊掉的字（「国内**宁门**主产地四川安岳」，本应是柠檬），模型在自己的叙述里写成了「柠檬」。库里原话和详细版引用都保持原样，改的只是模型自述，未违反「材料原文一个字不能改」。但这说明**模型会静默修正它认为是错字的东西**，万一某次修正的不是错字，人不会看见。是否要管留给产品所有者判断，暂不列为缺陷。

2026-08-23 修 PDF 快照与材料删除两件事，都由产品所有者在 P-005 上真用出来的。PDF 那条的根因不是「PDF 不支持」，是**类型判错**：网页快照永远叫 `snapshot.bin`，后缀说明不了任何事，`kind == "web_page"` 又把 PDF 判成了 HTML，于是二进制被当正文抽、抽出垃圾、垃圾长度过了门槛、两个键照给。改成先认文件头之后，PDF 明确「能看原件、扒不出原话、要引用请手工粘」。**没有引 PDF 解析库**——引了就等于让解析器的错字混进「原话必须逐字来自快照」这条硬不变量，这一步要不要走留给以后单独裁定。材料删除照「空节可去掉」的先例做：没挂东西的真删（连受控副本），挂了东西的拒绝并说清理由。**来源级的「这轮先不用」这次没做**——`sources` 表没有这个状态位，加它是 schema 0.8 的事，值得单独一轮讨论；眼下真正的需求是「升错了要能收拾」，那条已经解决。静态缓存升到 `?v=workbench41`，测试由 297 增至 305 全绿。

2026-08-23 界面按 PRD 第 20.8 节新定的设计基线改成 Notion 式文档感，触发点是产品所有者自己跑了一道题、记回来的七条流水账。**这一轮最值钱的不是换皮，是那张流水账里带出来两条一直没人发现的硬伤**：首页和工作台其实一直同屏（`#bench` 的 ID 选择器压过了 `[hidden]`），以及字号刻度和正文根本不是一把尺（`--fs-*` 用 rem 认 `html`，正文 17px 写在 `body` 上）。这两条都不是拍脑袋能想出来的，是用出来的。色板、字号、按钮四档、圆角边框的规则全部收进 `:root` 令牌并写进 PRD 20.8，回归测试新增一条断言：**规则里不许再出现写死颜色**（`:root` 之外的 `#xxxxxx` 一个都不许有）。旧暖色板 38 处写死值一并换成令牌。静态缓存升到 `?v=workbench42`，测试仍 305 全绿。

2026-08-23 补两件产品所有者在题目页上提的事。**一、建完题目之后模板就不再露面**——过两周回来只能靠题目名猜这道题用的是哪套问法。投影补 `template_name`（模板文件被挪走时退回 key，不让界面空着），首页每行一个弱色标签、工作台顶栏写「按「X」拆问题」。**二、导出可以顺手存到题目文件夹**（PRD 第 20.9 节）。

产品所有者原话是「材料的链接和文件都存在同一个文件夹，导出也导出到同一个项目文件夹」。**前半句其实早就成立**：受控副本本来就按题目分文件夹（`var/<db>-files/P-005/sources/S-022/snapshot.bin`），网页快照和上传文件都在那儿。缺的只有导出。**但没有把导出丢进那个文件夹**，关键理由是第三条（前两条只是不好用）：那里的文件名是对象 ID，人看不懂；路径深在代码目录里且被 gitignore；**受控副本是账本的一部分，不能跟人会去整理的文件混在一起**——人删掉一个快照，那条原话就失去了受控副本，追溯链断在那儿，而且系统不会提示。这跟第 8.27 节做 `remove_source` 时「挂了东西的一律不给删」是同一条道理。

落地：`<项目根>/导出/<题目名>/<日期> <整理稿|详细版>.<扩展名>`。题目名做文件名安全处理（去非法字符、剥首尾点和空格、超长截断、空名退回题目 ID），**同名不覆盖**、加 (2) (3)——上一版可能已经发出去了。存到哪儿不进账本；存不下也不吞掉已经导出的内容，只把原因说出来。`导出/` 已加进 `.gitignore`。新增 `tests/test_export_folder.py`，测试由 305 增至 **312 全绿**。

落地：模板配置加 `intro` / `steps` / `example` 三个纯界面字段；`GET /templates` 一并返回，并把七条问法原样带出来（介绍页要显示，且回归测试断言它必须等于该模板真实的 `recommended_question_labels`，不许介绍和实际问法两张皮）。首页加「模板都是干什么的」入口，展开是卡片式介绍页。**样例是静态文案不是材料**：底色和左竖线跟正文分开，文案里自己声明「不是材料，不能当证据用」，并有测试钉住这句话必须在。尽调那份的介绍必须写清「访谈问卷那段不在这个模板里」，也有测试钉住。静态缓存升到 `?v=workbench44`，测试由 312 增至 313 全绿。
