# P-001 P0 首轮可用性测试记录

> 日期：2026-08-12  
> 测试对象：P-001 P0 可点击低保真原型 v0.1  
> 测试性质：产品所有者首轮理解测试，不等于完整任务对照实验

## 1. 测试回答

1. 对“60%+”的理解：测试者识别为客户来源，但认为需要核实后才能写入报告。
2. 对冷链市场总产值材料的理解：用于最终报告中的冷链产业解析，即宏观层面。
3. 对带风险推进的理解：系统让用户选择风险处理方式。
4. 对结构化页面相对聊天的价值判断：测试者表示目前很难判断。

## 2. 结论与强制分类

### P0 必需修正

1. **客户提供信息的交付规则仍被误解。** 正确规则不是“外部核实后才能写”，而是可以立即以“据客户提供、口径待补”的方式进入内部稿；外部独立核实只影响核验状态和后续表述强度。原型需要直接显示这一动作规则，而不只显示状态标签。
2. **带风险推进只被理解为选择器。** 测试者没有主动提到系统已经创建 OverrideDecision、影响了哪个版本以及证据状态保持不变。确认结果需要明确显示“已创建记录、本版如何处理、什么没有改变”。

### 已通过本轮理解检查

- 宏观市场材料的分析层级和报告用途理解正确。
- 用户能找到带风险推进入口并理解三种处理方式属于风险处理选择。

### 后续验证假设

- “结构化工作流相对聊天是否值得”仍未得到验证。静态浏览不能证明返工收益，也不能证明维护负担；必须在一次包含多材料、引用回跳、附件失效或补料更新的实际任务中比较。

### 不做

- 不因本轮反馈增加券商、机场、轻量研究入口、完整工作台或 Agent。

## 3. 第一性原理判断

结构化工作流的成本发生在当下：用户要理解对象、状态和限制。收益主要发生在未来：补料、返工、恢复上下文和经理复核时减少重复劳动。因此只让用户浏览一版静态结果，天然无法证明后续收益是否大于当前成本。

当前不能判定 P0 可用性测试通过，也不能据此进入完整技术架构。下一轮必须让测试者完成一次状态发生变化的任务，例如：从内部稿返回“60%+”来源、对失效的市场材料选择带风险推进、再补入替代材料并判断哪些内容需要重审。

## 4. 已执行修正

原型 v0.2 已：

- 明示客户信息“当前即可带归属写入内部稿”，而不是等待外部核实；
- 将带风险推进确认按钮改为“确认处理并创建记录”；
- 确认后显著显示记录已创建、本版处理结果和“证据状态未改变”。

随后原型 v0.3 已补齐状态变化测试所需的最小交互：失效宏观材料的引用回跳、测试替代材料保存、新旧来源并存、快照/哈希反馈、受影响主张与初稿段落提示，以及局部重审决定。详见 [状态变化任务测试脚本](16_P-001_P0状态变化任务测试脚本.md)。

## 5. 下一决策门

完成一次带状态变化的P-001任务测试后，再判断：

1. 用户是否无需讲解即可正确处理客户来源；
2. 用户是否理解 OverrideDecision 的结果而不只是看到选择器；
3. 来源回跳、补料影响和局部重审是否明显减少恢复与返工成本；
4. 如果维护成本仍高于收益，是否收缩为报告中的来源与主张审查侧栏。
