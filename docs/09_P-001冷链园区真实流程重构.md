# P-001 冷链园区真实流程重构与产品要求

> 状态：依据现有历史成果重构；不是对完整项目事实的最终还原  
> 日期：2026-08-11  
> 用途：把真实售前研究过程转成经纬 MVP 的验证样本，而不是复刻一份旧报告。

## 1. 范围与证据边界

历史对话中曾提供：园区局部业态创新案例搜集、园区局部业态创新报告、P-001 冷链园区案例搜集、自身审视页面、中国冷链市场总产值数据，以及两张项目本体/案例分析页面。截至 2026-08-12，本机微信缓存中的前五个附件路径已失效，当前仍可访问的只有两张项目本体/案例分析图片。此前已经形成的观察继续保留为历史记录，但新一轮核验只能引用当前可访问材料；详见 [P-001端到端对象样本 v0.1](12_P-001端到端对象样本_v0.1.md)。

用户确认的过程是：团队先现场调研并拍照；实习生没有拿到完整客户材料；先做区位与周边冷链产业调研，再按一句话任务搜索园区局部业态改造或升级案例；讨论中引入产业图谱并提出延伸产业链等思路；之后继续做项目本体分析和冷链产业链延伸案例研究。

产品能力不受用户当时个人分工限制，可以辅助经理、顾问和分析师完成完整研究链。但求职或项目复盘中，必须继续区分团队成果、用户明确完成的工作和无法确认的历史内容。

## 2. 材料揭示的真实问题

现有成果共同指向的不是“做一份冷链行业报告”，而是一个资产与经营决策：面对区位和租金压力、空置空间、客群集中、产业链不完整等问题，项目还能引入什么功能或客群，为什么可能有效，需要什么条件。

已形成的结构性诊断包括：

- 现有客户以食品加工、仓储和配送相关企业为主，客群集中；
- 冷链功能空间相对有吸引力，普通厂房/仓储空间更难出租；
- 产业链主要集中在加工、仓储和运输等中游环节，上游研发/农资与下游销售/服务相对不足；
- 项目有冷链设施、交通和既有客户基础，但面临租金、区域竞争、空间条件和运营能力约束；
- 方向研究从泛化的园区业态创新，逐步收敛到交易、加工、选品、直播、展示、服务等产业链补链可能。

这些判断仍需要客户经营数据、空间参数、租约、改造成本、需求访谈和政策适用性进一步验证，不能直接等同于最终建议。

## 3. 重构后的真实工作方式

### 3.1 决策主干（经）

```text
现场观察/一句话委托
→ 明确要解决的经营与空间决策
→ 建立问题与候选解释
→ 并行研究与补料
→ 讨论、否决或调整假设
→ 形成结构性诊断
→ 生成候选方向
→ 初步可行性筛选
→ 内部评审或售前沟通材料
```

### 3.2 分析工作包（纬）

| 工作包 | 主要问题 | 示例输出 |
|---|---|---|
| 项目本体与运营 | 什么空间空、为什么空、现有设施和租户能支持什么 | 本体卡、租户/空间结构、约束清单 |
| 区位、市场与竞争 | 为什么设在这里，周边供需和替代项目如何 | 区位结论、市场/竞品对比 |
| 客群与产业链 | 现有客群集中在哪里，链条缺什么，延伸机制是什么 | 可编辑产业图谱、缺口与依赖 |
| 政策 | 哪些政策构成机会、限制或申请条件 | 政策证据卡、适用性判断 |
| 案例与竞品 | 别人解决了什么问题、采取什么机制、能否迁移 | 案例卡、排除理由、迁移条件 |
| 数据分析 | 数字口径是否可靠，趋势和预测支持什么 | 数据表、计算、异常与来源 |
| 可行性 | 方向是否适配空间、需求、经济性、监管和运营能力 | 选项矩阵、风险、最小验证动作 |

工作包不是固定顺序。经理可以先要求案例，讨论后再补产业链；现场照片也可能推翻某个空间假设。每个工作包可处于未开始、进行中、暂时够用、待补数据、受质疑或已替代。

## 4. 为什么这不是回到“七层”

七层的问题不是有七种分析，而是把分析维度误当成必须顺序完成的流程。P-001材料反而证明：案例、本体、产业链和数据会互相来回影响，且部分案例会被标成“废案例”后排除。

因此经纬的稳定骨架应是“问题—证据—发现—选项—决策”，区位、产业链、政策和案例只是按需调用的工作包。一个项目可以只运行其中三个，也可以在售前阶段把某个工作包标记为“暂时够用”后先输出讨论稿。

## 5. 普通 Prompt 暴露出的边界

现有《园区局部业态创新报告》可以快速给出大量案例和 A/B/C 方向，证明普通聊天适合发散。但材料也暴露出典型问题：案例相关性不稳定、来源不完整、项目条件未绑定、成功案例容易被直接类比为本项目建议。

相反，案例搜集页面中保留了筛选、归类和“废案例”，说明真实价值来自研究过程中的人工判断与方向收敛，而不只是生成更多文字。

中国冷链市场数据表还显示另一类风险：数值全部为硬编码，缺少来源、实际/预测标识和公式，部分增长率与相邻年度规模变化不闭合。系统必须把这类问题作为数据 QA 提示，而不是把表格直接画成可信图表。

## 6. 从P-001案例导出的 P0 产品要求

1. **低信息创建项目**：一句话、地点、照片或少量旧文件即可启动。
2. **问题与假设板**：把“为什么空置”“缺哪一段链条”“什么功能可能有效”保存为可编辑对象。
3. **并行研究工作包**：按任务启用本体、区位、产业链、政策、案例、数据和可行性。
4. **材料收件箱**：网页、PDF、Word、Excel、图片、访谈纪要和人工判断进入同一项目。
5. **证据台账**：保存原文、位置、时间、地域、口径、来源等级和支持/反驳关系。
6. **案例卡与排除记录**：记录案例起点、干预机制、运营方式、结果主张、迁移条件和不适用原因。
7. **可编辑产业链图谱**：显示环节、参与者、现有覆盖、缺口和延伸依赖，而不是一次性生成图片。
8. **数据与公式 QA**：检查单位、来源、实际/预测、公式和变化率闭合。
9. **选项与可行性卡**：按空间、需求、客户、政策、经济性和运营能力比较方向。
10. **补料影响追踪**：新材料进入后只提示受影响的发现、选项和页面，并保留旧版本。

## 7. 宽验收如何落地

不是每个工作包都必须完整验收，但每个被采用的结论至少需要：证据或明确的假设标签、来源/缺口、替代解释、人工可修改/否决状态。

项目采用三档决策门：

1. **可继续头脑风暴**：初始问题、假设、未知项和第一轮线索已形成；
2. **可供内部评审**：形成结构性诊断、支持与反证、候选方向和下一步验证；
3. **可用于售前沟通**：结论强度与证据匹配，明确客户数据请求、正式项目方法和限制。

售前材料的目标不是证明方案已经可落地，而是证明团队理解问题、已有有据可查的方向，并知道正式项目下一步要验证什么。

## 8. 仍然缺失但不阻塞原型的信息

- 领导最终保留、否决或调整了哪些方向；
- 客户当时真正希望解决的是出租率、租金、产业集聚、运营收入还是其他目标；
- 项目空间、租约、改造成本、设施能力和合规约束；
- 哪些页面进入了内部讨论或对客材料；
- 后续是否进入正式项目，以及客户反馈。

这些内容统一标记为未知，不需要为了做原型而补写历史。原型先测试系统能否保存变化、暴露缺口并支持人机交替推进。
