## 1. 当前不能改变的范围

当前已收口的验证范围：

```text
一句话任务 / 少量材料
→ 一块工作台看见本轮要决定什么
→ 本轮问题进度（还没写 / 草稿 / 这轮够用了）
→ 按问题搜材料，打开后升为 Source，挂上原话
→ 模型写一节给经理的稿，人收下或改
→ 机械检查（无来源标红，可收下）
→ 本轮先收口，上一轮问题归档，开下一轮
→ 导出 Word
```

P0（P-001 冷链园区低信息售前写稿闭环）已由产品所有者于 2026-08-19 收口。默认产品面仍是这块工作台，不变量仍有效。不要再把 P0 当未完成的开发任务。P1 第一刀（拆本轮问题）与第二刀（轮次归档、材料对应问题、看快照、靠材料写稿）已写入；不要开始画布、无人值守 Agent 或第二业务。

当前不开发（P0 收口不改变这条）：

- 券商降本增效模板；
- 机场外摆或机场商业策划模板；
- 轻量研究/结构化项目的封闭双模式入口；
- 完整画布、团队看板和故事线平台；
- Agent 或 Multi-Agent；
- 企业知识库、组织权限和专业数据库集成。

这些内容只是后续验证候选，不能因聊天中出现一个例子就进入开发。P0 收口不等于批准 P1。

## 2. 已确认的长期愿景

长期愿景仍是“咨询证据到决策工作台”，不是一次性P-001工具。P0 收窄的是当前验证范围，不是把未来路线删除。

接到写稿页的顺序（P0 已做成并收口）：

```text
领导一句话 / 新题目
→ Brief：这轮要决定什么、本轮问题
→ 按问题搜材料：只产出候选链接，人打开后升为 Source
→ 现有工作台：写一节、收下、标红、材料匣
→ 导出 Word
```

现在「搜」已接上：人触发按本轮问题搜，只产出候选链接，人打开后升为 Source。公开搜索被拦截时不得假装没搜到。写稿页所有者已认为完成度够用，停止打磨。搜不是无人值守 Agent。2026-08-19 所有者裁定 P0 收口；docs/22 计时对照仍跳过。其后才是愿景阶段，须先写入 PRD 才开发：

1. P1 个人咨询工作台：画布、简化看板、更多地产产业模板、Office 联动、单一研究 Agent（可把搜做成可替换 ExecutionStrategy）；
2. P2 团队工作台：分工、审批、团队知识与重复研究；
3. P3 企业平台候选：权限、部署、数据库连接、跨项目复用和经验证的 Agent 编排。

## 3. 如何避免 MVP 做完后无法扩展

当前要预留的是稳定接缝，而不是未来页面和空功能：

| 变化 | 预留方式 |
|---|---|
| 新项目类型 | ProjectTemplate / AnalysisModule，不改变核心对象 |
| 新材料来源 | SourceAdapter / Parser / WebSearchAdapter |
| 新分析能力 | AnalysisArtifact |
| Workflow / Agent | 可替换的 ExecutionStrategy |
| Word/PPT/Excel | DeliverableExporter |
| 画布/看板/故事线 | 同一对象的不同视图，不复制状态 |
| 团队与权限 | 后续 Role/Task/Organization 对象 |
| 月报和监测 | 后续 Schedule/Snapshot 对象 |

开发前必须遵守：

- P-001业务词只能出现在模板和样本中，不能写死在核心 schema；
- 核心主链保持 Source—EvidenceExcerpt—Claim—Finding/Option—DeliverableBlock；
- schema 有版本，字段变化有迁移；
- 人工编辑、来源快照、评审和覆盖决定不能被重新生成覆盖；
- 内部编号稳定但默认对用户隐藏；
- 不以万能 metadata、复制页面或复制数据库冒充扩展性。

## 4. 最近一次可用性反馈及修正

用户反馈：

1. “60%+”属于客户提供的信息，可以进入报告；正确处理是标为“据客户提供、口径待补”，而不是一律禁止写入。
2. 中国冷链市场总产值数据属于宏观市场分析，恢复并核验后可用于行业前景与市场表现。
3. 来源到报告的追溯结构有启示价值。
4. “带风险推进”点击反馈不明显或无法感知。
5. `S-002`、`C-002`、`DB-001` 等编号对普通用户不友好。
6. 单一简单任务直接与 AI 对话更方便；这不要求 P0 增加轻量研究入口。当前只证明P-001这种多问题、多材料、会补料和返工的任务是否值得结构化。

已决定的局部修改：

- 普通界面隐藏技术编号，改用自然语言名称；
- 区分“客户提供”与“外部独立核实”；
- 给冷链市场数据明确“宏观市场分析”归属；
- 带风险推进必须出现明显、即时的处理结果；
- 不因此增加券商、机场或双模式功能。

已裁决的范围与扩展口径：

- “轻量研究/结构化项目”只作为早期工作深度预设示例，不是未来工作台对课题的封闭二分，也不写成核心 schema 的固定枚举；
- P0 只实现P-001所需的结构化研究闭环，不增加轻量研究入口或两套流程；
- 未来工作形态通过 ProjectTemplate、AnalysisModule、ExecutionStrategy 和同一对象的不同视图组合扩展；
- P0 固定使用 Workflow，只保留 ExecutionStrategy 接缝；单一研究 Agent 属于 P1 的条件性验证，Multi-Agent 继续延后。

**为什么导出不跟受控副本混放，这条要记住**：那里的文件名是对象 ID（人看不懂）、路径深在代码目录里（不是放交付物的地方），但真正的理由是第三条——**受控副本是账本的一部分，不能跟人会去整理的文件混在一起**。人删掉一个快照，那条原话就失去了受控副本，追溯链断在那儿，而且系统不会提示。这跟第 8.27 节 `remove_source`「挂了东西的一律不给删」是同一条道理：**能删的和不能删的必须分开放。**

两条防御要保住：**同名不覆盖**（加 (2) (3)；上一版可能已经发出去了），**题目名做文件名安全处理**（去非法字符、剥首尾点和空格、超长截断、空名退回题目 ID）。存到哪儿不进账本，存不下也不吞掉已经导出的内容。

硬门槛是「原话必须逐字来自快照」。**但那道门槛挡不住来源本身是假的。** 实搜反复撞到三类：**扒得出但不是法定口径**（渠道商 SEO 页、镜像站，原话照样扒得出）、**搜得到但扒不出来**（问答社区、种草社区、招聘站挡爬虫）、**官网抓不到不等于这家没有公开信息**（前端渲染的官网只回网页标签，要退到应用商店页或帮助中心，否则会把技术问题误报成事实结论）。

**一句话：扒得出原话，不等于这个来源算数。** 已经写进介绍页。**这个只有真的去搜才撞得到——推理是推不出来的。**
