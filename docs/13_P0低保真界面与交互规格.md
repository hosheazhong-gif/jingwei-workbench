## 1. 设计判断

P0 不以 0—7 分析画布、团队看板或四工作区作为首页。默认界面是“内部稿 + 来源与主张审查侧栏”：用户先阅读和编辑内部稿；点击段落时，再查看该段落能否写入、依据、来源、风险处理和受影响范围。

底层继续保留完整对象链：

```text
Brief / ResearchQuestion
→ Source / EvidenceExcerpt / Claim
→ Finding / Option
→ Draft / Review / Override
```

报告、审查侧栏和补料影响提示是同一批对象的不同投影。用户可以从报告段落定位到 Claim 和来源；补充材料后，系统只指出受影响的判断与段落，等待用户局部复核，不直接覆盖旧稿。四工作区保留为未来复杂项目的深度视图假设，不在 P0 实现。

`S-002`、`C-002`、`DB-001` 等编号只用于内部追溯、开发和审计。普通用户默认看到“项目本体分析页”“食品客群占比”“项目问题”等名称；只有在展开技术详情时才显示编号。

## 2. 当前默认界面结构

界面固定保留：内部稿正文、当前版本、补充材料入口和段落级审查侧栏。用户选中段落后，侧栏显示来源归属、核验状态、写入规则、风险处理和版本影响。

“带风险推进”和“更新内部稿”仍是两个动作：前者生成 OverrideDecision，后者生成或更新 DeliverableBlock。系统不得因为用户更新内部稿，就自动改变 Claim 核验状态。

### 决策门

P0 只显示当前最有意义的一档状态，例如“可继续头脑风暴”。不显示统一完成百分比，也不要求所有研究问题结束。

## 3. 底层投影一：Brief / ResearchQuestion

### 目的

把一句话任务转换成可编辑的本轮研究边界，避免用户先填写一整套项目表单。

### 首屏字段

- 历史情境或原始委托；
- 当前需要支持的决策；
- 本轮交付；
- 已知、假设、未知；
- 本轮必要 ResearchQuestion；
- 每个问题的“暂时够用”条件和状态。

### P-001示例

只显示 RQ-01、RQ-02、RQ-04、RQ-06 等当前必要问题，不预先展开完整区位、政策、产业链和可行性框架。

### 验收重点

用户应能在一分钟内回答：系统理解的任务是否正确、当前准备交什么、哪些内容不知道。

## 4. 底层投影二：Source / EvidenceExcerpt / Claim

### 目的

这是 P0 最关键的差异化界面：让用户看到“来源说了什么”和“系统/顾问如何解释”是两层对象。

### 三栏布局

1. **来源栏**：文件/网页标题、可访问状态、来源质量、快照和哈希状态；
2. **原子主张栏**：Claim 文本、认识类型、核验状态；
3. **证据定位栏**：页码、单元格、网页位置或图片区域、精确摘录、上下文限制。

窄屏时三栏按来源—主张—证据顺序堆叠，不压缩成无法阅读的小列。

### 核心状态

- `available`：可打开项目快照；
- `path_expired`：临时外部路径失效；
- `captured`：已捕获来源陈述；
- `unverifiable`：当前无法确认口径或原始事实；
- `inference` / `judgment`：明确区别于 factual_claim。

### P-001默认交互

选择“食品客群占比”时，右栏定位至项目本体分析页左下“60%+ 食品产业客群”。如果该信息确由客户明确提供，可以写入报告并标为“据客户提供”，但客户来源不等于外部独立核实；分母、时点和统计口径仍应保存。

界面必须直接显示交付动作：“当前即可带归属写入内部稿；不需要等待外部独立核实，但不得省略客户归属和口径缺口。”只显示“客户提供/未独立核实”状态不足以避免用户误解。

选择“中国冷链市场总产值数据”时，应显示它属于“宏观市场分析”材料：恢复文件并核对来源、实际/预测和公式后，可以用于报告的行业前景与市场表现部分。当前路径失效时不显示虚构数值，而显示重新上传和受影响内容。

### 验收重点

用户应能准确回答：

1. 这句话来自哪个文件的哪里？
2. 它是来源事实陈述、推断还是顾问判断？
3. 当前检查到了什么程度？
4. 为什么它还不能作为对客事实？

## 5. 底层投影三：Finding / Option

### 目的

帮助顾问从材料跨越到综合判断，同时保留支持、反证、替代解释和缺口。

### Finding 必显内容

- 当前观察；
- 支持 Claim；
- 替代解释或反证；
- 信息缺口；
- 当前强度。

### Option 必显内容

- 候选方向；
- 当前依据；
- 主要风险；
- 下一最小验证动作；
- 当前状态。

P-001的三个方向状态均为 `candidate`，界面显示“待验证方向”或“研究假设”，不设置伪精确总分。在空间、需求、合规、成本和运营数据补齐后，才允许启用更完整可行性比较。

## 6. 当前主界面：Draft / Review / Override

### 目的

生成能进入经理讨论的可编辑内容，并让每个关键段落保持证据连续性。

### 交付块

左侧显示故事线或内容块，右侧显示当前内容、引用和追溯链。例如：

```text
报告段落
← 食品客群占比
← 图片摘录
← 项目本体分析页
```

点击 Claim 引用，应回到界面二并定位相应 EvidenceExcerpt。

### 人工评审

每个 DeliverableBlock 可：

- 批准；
- 退回修改；
- 从本版排除。

人工编辑和 ReviewDecision 必须保存，后续重新生成不能静默覆盖。

### 强制推进

当资料不齐时，用户可以选择：

- 按假设推进；
- 从本版排除；
- 以区间/情景表达。

系统记录 OverrideDecision，并在版本中保留限制。“食品客群占比”仍然可以是“客户提供、口径待补”，“共享/柔性加工”等方向仍然可以是“待验证方向”。用户点击后必须立即看到“记录已创建、作用于哪个版本、本版如何处理、证据状态未改变”，不能只看到选择器或页面底部不明显的状态文字。

## 7. 纵向闭环必须实现的关键交互

1. 点击报告段落，看到其写入条件、来源归属、主张状态和证据位置；
2. “食品客群占比”可按“据客户提供、口径待补”写入，不把客户来源误写成独立核实；
3. 宏观市场材料只作用于冷链产业解析中的行业背景判断、行业前景与市场表现；
4. 新文件补入时保存快照和哈希，并明确说出受影响的判断与段落；
5. 系统等待用户局部复核，不自动覆盖已审核内部稿；
6. 对段落批准、退回或排除，并保存 ReviewDecision；
7. 选择风险处理方式后生成 OverrideDecision，明确版本作用范围，但证据状态不变。

## 8. 设计中刻意没有加入

- 0—7 完整咨询画布；
- 团队任务看板、负责人和截止时间；
- Multi-Agent 运行过程；
- 精装 PPT 编辑器；
- 复杂评分模型、统一完成百分比；
- 企业知识库和跨项目搜索；
- 组织权限和审计后台。

这些能力仍在路线图中，但不能用来证明当前 MVP 成立。

## 9. 已完成的历史测试

四工作区原型曾让测试者完成：

1. 找到系统对项目问题的理解并指出一处需要修改的地方；
2. 找到“60%+”并解释为什么它不是已核实事实；
3. 找到东方甄选案例方向，并说明仍缺什么；
4. 在附件失效时继续生成内部头脑风暴稿；
5. 从初稿的一条引用返回来源位置；
6. 补充一份替代材料并判断哪些内容需要重审。

观察指标：

- 是否无需讲解就理解三种状态；
- 是否出现把 `captured` 当作“事实已证实”的误解；
- 完成追溯所需点击数和时间；
- 用户是否觉得 Claim 维护负担超过返工收益；
- 是否仍需要回到聊天或手工文档才能完成任务。

## 10. 当前下一步决策门

四工作区原型的两轮测试未通过，报告优先方案随后通过本轮理解门槛：用户能准确说出新材料影响“行业背景判断”和“行业前景与市场表现”，并理解系统会等待重新审核。因此可以进入可运行纵向闭环，但这不等于 P0 产品价值已验证。

下一门槛是用真实P-001流程验证：报告投影、补料影响定位和局部复核是否比普通聊天或人工文档减少关键事实错误、上下文恢复和重复返工。未通过前，不增加四工作区、完整工作台、第二业务场景或 Agent。
