# PRD v0.1｜经纬咨询决策工作台（历史版本）

> 本文件保留为版本记录。2026-08-11 的 JD 深挖显示，本版对咨询工作描述过于抽象，缺少项目类型、具体工作步骤、交付物和岗位能力映射。当前产品与 MVP 基线请使用 [PRD v0.4](01_PRD_v0.4.md)。

## 1. 产品命题

咨询顾问经常在浏览器、数据库、访谈纪要、Excel、Word、PPT 和即时沟通之间重复搬运内容。现有通用 AI 可以生成文字，但很难持续回答：

- 我们现在究竟要支持什么决策？
- 哪个假设已被验证，哪个还缺证据？
- 这条结论来自哪一页、哪张表、哪个访谈？
- 数字变化后，哪些图表、结论和页面必须更新？
- 哪些内容是事实、推断、顾问判断或客户确认？
- 最新一轮内审改变了什么？

经纬用结构化项目对象把上述链条连接起来。

## 2. 目标用户

### 核心用户

- 战略、管理、商业和地产咨询团队的 Analyst / Associate / Consultant；
- 企业内部战略、商业分析和战略运营团队；
- 需要快速完成前期研究、投标或专项分析的小型咨询团队。

### 关键协作者

- Project Manager：定义问题、审查假设和控制交付质量；
- 专家/访谈对象：提供行业和企业证据；
- 客户团队：确认事实、约束、优先级和行动；
- 数据/设计团队：提供模型、图表、GIS 和页面支持。

## 3. 核心 Job to Be Done

> 当我收到一个定义不清、时间紧、资料分散的客户问题时，帮助我快速建立可审查的问题结构和证据计划，完成研究与分析，形成少量可比较的策略选项，并生成能进入内部讨论的交付初稿；同时让我清楚知道每条结论的依据、缺口和责任边界。

## 4. 产品中的核心对象

| 对象 | 回答的问题 |
|---|---|
| Project | 这是哪个项目，范围、团队、节点和保密级别是什么？ |
| Decision | 客户最终要做出什么决定？ |
| Question | 为支持该决定，必须回答哪些问题？ |
| Hypothesis | 当前暂定判断是什么，如何证伪？ |
| Workstream | 哪个模块由谁在何时完成？ |
| Evidence | 事实来自哪里，可信度、时间、口径是什么？ |
| Analysis | 使用了什么方法、输入、公式和假设？ |
| Insight | 多条证据共同说明了什么？ |
| Option | 有哪些可行选择，条件、价值和风险是什么？ |
| Recommendation | 为什么建议选它，谁确认，适用条件是什么？ |
| Deliverable | 结论进入了哪份备忘录、表格、页面或工作坊？ |
| Review | 哪条批注改变了哪个对象和版本？ |

## 5. 核心工作流

### 阶段 A：定义任务

- 上传或粘贴任务说明、会议纪要、招标文件；
- 提取客户、决策、范围、交付物、时间、限制和未知项；
- 生成“任务理解卡”，由顾问确认；
- 任何未确认信息不得自动当作项目事实。

### 阶段 B：结构化问题

- 生成初版问题树和假设树；
- 检查 MECE 不是目标本身，重点检查能否改变决策；
- 为每个问题标记优先级、依赖、负责人和完成定义；
- 顾问批准后才进入批量研究。

### 阶段 C：证据与分析计划

- 为假设建立所需证据、数据字段、访谈对象和分析方法；
- 区分一手/二手、内部/外部、定量/定性；
- 标记来源等级、时效、适用区域和潜在偏差；
- 形成研究清单、访谈提纲和数据请求清单。

### 阶段 D：研究与建模

- 网页和报告检索；
- PDF、PPT、Word、Excel 和网页信息抽取；
- 访谈纪要结构化；
- 表格清洗、口径统一、数据质量检查；
- 市场、客户、竞争、财务、空间或运营分析；
- 每个结果保存输入、公式、假设和运行版本。

### 阶段 E：洞察与选项

- 把事实和分析综合为洞察，不直接把摘要称为洞察；
- 显示支持证据、反证、置信度和信息缺口；
- 生成多个策略选项并按客户确认的标准比较；
- 计算或估计影响、难度、风险、资源和时间；
- 关键取舍必须由人确认。

### 阶段 F：交付与评审

- 生成决策备忘录、故事线、PPT 页面草稿、Excel 附表和工作坊材料；
- 检查数字跨文件一致性、引用覆盖率、结论—证据一致性和页面逻辑；
- 将批注绑定到具体结论、数据或页面，而不是只留在聊天记录里；
- 新版本自动提示哪些下游内容可能失效。

### 阶段 G：行动与学习

- 将建议转成行动项、负责人、里程碑、指标和风险；
- 保存客户确认与未决问题；
- 项目结束后沉淀可脱敏的方法模板、指标定义和案例卡；
- 客户机密和跨客户知识严格隔离。

## 6. 六个产品空间

1. **项目驾驶舱**：任务、决策、节点、团队、进度和风险；
2. **问题与假设树**：问题拆解、优先级和验证状态；
3. **证据室**：来源、文件、摘录、访谈、数据口径和引用；
4. **分析工作台**：表格、模型、GIS、图表、情景和检查；
5. **综合与选项板**：洞察、反证、选项、评分、建议和审批；
6. **交付与审阅室**：故事线、PPT/Word/Excel、批注和版本影响。

聊天只是每个空间内的辅助交互，不是产品的唯一界面。

## 7. 模板体系

### T0：通用策略项目

提供任务定义、问题树、证据计划、洞察、选项和交付闭环，不预设行业分析目录。

### T1：产业、地产与区位策略（经纬优势模板）

覆盖产业边界、市场与客户、竞争与价值链、本地/空间条件、项目能力、机会经济性、定位和实施。

### T2：市场与竞争监测

覆盖固定字段采集、来源更新、异常核验、时间/区域比较、变化解释和月报生成。首个真实验证案例为 JLL 产业园月报。

### 后续候选模板（不进入首版开发）

- 增长与市场进入；
- 商业策略、定价与 GTM；
- 企业/业务单元战略与组合；
- 运营模式与转型；
- 商业尽调与交易策略；
- 公共部门与区域战略。

## 8. MVP 范围

首个 MVP 只证明一个闭环：

> 输入任务说明和一组来源文件 → 确认决策与问题树 → 建立证据库 → 完成一组结构化分析 → 形成带引用的洞察和选项 → 输出内部讨论版备忘录/页面大纲 → 通过自动质检。

### MVP 必须有

- 项目、决策、问题、假设、证据和洞察对象；
- 文件/网页摘录与精确引用；
- 人工确认门；
- 可编辑的研究计划；
- 结构化表格和数字口径检查；
- 洞察到证据、建议到洞察的双向追溯；
- 内部讨论版故事线和页面大纲；
- 版本与批注影响提醒；
- 通用策略模板 + 市场监测模板。

### MVP 暂不做

- 自动生成“最终可发客户”的完整百页 PPT；
- 全自动专家访谈或替代客户沟通；
- 同时覆盖所有策略项目类型；
- 无审核自动发布外部结论；
- 直接复刻任何咨询公司的专有框架或模板；
- 把向量数据库当作产品卖点。

## 9. 质量与安全原则

- 每个关键数字必须有单位、时间、区域、口径和来源；
- 事实、推断、顾问判断、客户确认和未来建议分开标识；
- AI 生成内容在进入“已确认结论”前必须经过人工批准；
- 网页内容视为不可信输入，防范提示注入和恶意内容；
- 客户资料默认本地或受控环境处理，不用于跨客户学习；
- 输出前自动检测无来源数字、失效链接、冲突口径和未脱敏字段；
- 模型和公式必须可复算，无法复算的结果降低证据等级。

## 10. 成功指标

初期先测基线，不预先虚构“节省 80% 时间”等结果。

- 从收到任务到形成经人工确认的问题树所需时间；
- 从启动研究到形成第一版可讨论故事线所需时间；
- 关键结论的精确引用覆盖率；
- 数字跨表格/页面一致性错误数；
- 顾问对 AI 建议的接受、修改和否决比例；
- 内审后返工涉及的对象数量和原因；
- 相比原流程减少的重复复制、搜集和格式整理时间；
- 最终仍需人工完成的高判断工作占比。

## 11. 已确认的产品决策

- 决策是顶层对象，行业不是；
- 工作流与分析框架分离；
- 证据图谱优先于聊天历史；
- AI 负责加速和检查，人负责范围、取舍与承诺；
- 地产/空间策略是差异化模板，不是产品上限；
- 先验证一个真实闭环，再决定是否做完整平台。
