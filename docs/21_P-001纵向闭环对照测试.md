# P-001纵向闭环对照测试

> 日期：2026-08-13  
> 产品基线：PRD v0.4 §15.2、§16  
> 对照对象：原人工流程、普通 AI 聊天、可运行经纬最小闭环  
> 测试性质：能力基线对照，不是真人计时 A/B，不预设节省百分比

## 1. 本轮能对照什么、不能对照什么

本轮对照的是已经跑通的P-001样本闭环，不是从一句全新任务现场生成报告，也不是顾问计时实验。

已纳入对照：

- 打开内部稿并按段落审查来源、口径和核验限制；
- 失效宏观材料不发明数字、不发明未关联段落；
- 带风险推进不改变主张核验状态、不覆盖当前稿；
- 新材料创建新 Source，旧哈希保留；
- 影响预览只沿显式关系计算，不改写内部稿；
- 排除段落和未采用候选不进入 Markdown 导出；
- 关闭后重开同一数据库，对象 ID、正文、评审和覆盖记录仍在。

明确未纳入、不得写成已验证：

- 到第一版可审查初稿的真实耗时；
- 用户修改、排除和补证次数的真人统计；
- 输出进入 Word/PPT 后需要重做的程度（已有可编辑 Word，排版返工未测）；
- 用户是否愿意在第二个真实任务继续使用；
- Parser 从新文件自动写入摘录或数字。

这些项按 PRD「首轮先建立基线」保留为后续验证假设。

## 2. 三条路径

### 2.1 原人工流程

依据 [P-001 冷链园区真实流程重构](09_P-001冷链园区真实流程重构.md)：现场观察 / 一句话任务后，区位、本体、案例、产业链等工作包并行推进；讨论会改变假设；部分附件后来路径失效；案例搜集里保留了筛选和“废案例”；市场数据表曾出现硬编码数值、缺来源/公式、增长率不闭合。

返工主要发生在：跨 Word/PPT/聊天记录复制、附件失效后无法回到精确摘录、把发散案例直接当成项目建议、以及数字口径无法回查。

### 2.2 普通 AI 聊天

同一材料下，普通 Prompt 适合快速发散案例和方向，但来源不完整、项目条件未绑定、成功案例容易被类比为建议；新一轮对话通常无法恢复上次排除、覆盖和口径限制。补入带数字的新文件时，聊天倾向于把文件内容写进稿，而不是先标为待核验。

### 2.3 经纬最小闭环（本轮可运行）

```text
导入P-001样本
→ 打开内部稿
→ 从「项目问题」回到客户提供的「60%+ 食品产业客群」及口径限制
→ 对失效的「中国冷链市场总产值数据」只看到显式判断，不发明市场规模段落
→ 段落级带风险推进
→ 捕获替代材料（新 Source + SHA-256，不覆盖旧文件）
→ 影响预览并入旧显式链，不改写 current_text
→ 排除段落 / 保存未采用候选
→ Markdown 导出当前内部稿
→ 重开同一数据库恢复状态
```

界面仍是内部稿 + 审查侧栏。可执行走查见 `tests/test_case-p001_loop_comparison.py`。

## 4. 与原型文案的差异（必须保留）

报告优先原型测试里，用户说出的影响范围是「行业背景判断」和「行业前景与市场表现」。

可运行样本中，失效宏观来源 `S-007` 的显式链只到达判断「当前最严重的问题是证据链断裂，而不仅是信息量不足」，**不**连接到名为「行业前景与市场表现」的段落。这是不变量：宏观市场材料只支持宏观判断，不能单独证明项目需求，也不能发明未关联段落。

对照时不得把原型理解测试的段落名称当成当前对象样本已经具备的报告段落。

## 5. 相对两条旧路径，现在能减少什么

相对普通聊天，可运行闭环已经能减少：

1. 把客户口述写成已核实事实；
2. 把失效或新补的市场文件直接写成市场规模数字；
3. 中断后靠记忆恢复「这段为什么能写 / 不能写」；
4. 排除和未确认修改在导出时被重新混入正文。

相对原人工流程，可运行闭环已经能保存：

1. 来源快照与哈希，而不是只留一个会失效的微信路径；
2. 主张、限制和段落的同一对象 ID，而不是报告里一份、审查里另一份；
3. 带风险推进与核验状态分离。

仍不能声称：

- 顾问总体更快；
- 维护结构化对象的成本已被真实任务抵消；
- Markdown 导出已经解决 Office 交付返工。

## 6. 强制分类

### P0 必需修正

本轮对照没有发现必须立刻改代码才能继续验证的断裂。闭环按 docs/19 最小链路可顺序走通。

### 后续验证假设

- 真人按 [状态变化任务测试脚本](16_P-001_P0状态变化任务测试脚本.md) 对**可运行界面**再测一次，记录耗时、修改次数和是否愿意做第二个任务；
  现行脚本为 [P-001可运行界面真人测试脚本](22_P-001可运行界面真人测试脚本.md)；2026-08-14 产品所有者裁决暂不填写，改为先能新建题目；
- Word 导出器是否明显减少排版重做；
- 从一句全新任务**生成内部稿**仍是后续验证假设；空白题目与 Brief 已可创建，但不自动成稿。

### 不做

- 不因对照缺口补做券商、机场、完整工作台、问题拆解视图或 Agent；
- 不把原型里的「行业前景与市场表现」段落补进样本来“对齐文案”；
- 不编造节省百分比。

## 7. 结论与下一决策门

**能力基线对照成立：** 经纬最小闭环在来源覆盖、口径限制、补料不覆盖、中断恢复上，已经可与普通聊天和原人工流程区分。

**产品假设尚未完全成立：** 真实返工收益、维护成本和 Office 交付仍未用真人任务证明。

2026-08-13 产品所有者确认：能力基线足够进入个人工作台**视图讨论**。这不改变默认界面，也不等于 P1 开工。

真实返工收益、维护成本和 Office 交付仍未用真人任务证明。

约束：新视图只能做同一对象的 `ViewProjection`，不能保存第二套结论；首页保持「内部稿 + 审查侧栏」。四工作区作为默认导航已经失败。
