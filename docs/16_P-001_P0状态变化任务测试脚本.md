# P-001 P0 状态变化任务测试脚本

> 日期：2026-08-12  
> 原型版本：v0.3  
> 后续：可运行界面请改用 [P-001可运行界面真人测试脚本](22_P-001可运行界面真人测试脚本.md)；本文件只保留原型任务原文

> 目的：验证结构化项目在附件失效、风险推进和补料重审时是否比一次性聊天更容易恢复与返工

## 1. 测试前说明

只给测试者一句情境，不解释 Source、Claim、OverrideDecision 等内部术语：

> 经理准备看内部稿，但冷链市场数据附件打不开。请先确认当前稿如何处理该材料，再补入一份替代材料，并判断哪些内容需要重审。

原型中的“冷链市场资料_替代样本.xlsx”是状态变化测试材料，只用于模拟文件保存、哈希、影响提示和重审；不包含也不生成任何市场数值。

## 2. 测试任务

测试者独立完成：

1. 进入“内部初稿”，找到“行业前景与市场表现”；
2. 从该段落返回宏观市场材料，说明为什么当前没有数字；
3. 在附件失效的情况下选择一次“带风险推进”，说明系统创建了什么记录、当前版本如何处理、什么状态没有改变；
4. 点击“补充材料”，保存测试替代材料；
5. 查看系统指出的受影响内容；
6. 在“保留段落并标记待重审”和“从本版排除宏观段落”之间作出选择；
7. 回到内部初稿，确认系统没有自动写入数字或覆盖原段落。

## 3. 测试后只问五个问题

1. 新材料加入后，哪些内容需要重审？
2. 为什么新文件已经可打开，市场数字仍不能直接写入？
3. 带风险推进改变了什么，没有改变什么？
4. 如果改用普通聊天，你需要自行记住或重新核对哪些内容？
5. 这一套状态和操作带来的返工收益，是否值得其理解与维护成本？

## 4. 通过条件

必须同时满足：

- 测试者能识别受影响的“宏观市场规模与表现”主张和“行业前景与市场表现”段落；
- 测试者不把“文件可访问”误解为“数字已核验”；
- 测试者理解带风险推进改变版本处理，不改变证据核验状态；
- 测试者能在不重新生成整份报告的情况下完成局部重审；
- 测试者能够说出相对聊天减少的恢复或返工动作，而不是只评价界面是否清楚。

## 5. 失败后的处理

- 若用户看不懂状态：先修改措辞与反馈，不增加新功能；
- 若用户能理解但操作明显繁琐：减少需要人工维护的对象和状态；
- 若用户说不出相对聊天的返工收益：不进入完整工作台架构，优先测试“报告中的来源与主张审查侧栏”；
- 不因测试失败增加券商、机场、轻量研究入口、完整工作台或 Agent。
