# 对象模型与工作流｜PRD v0.4

> 日期：2026-08-12  
> 状态：当前对象模型基线

## 1. 建模原则

经纬不把一份 AI 长文作为项目状态。系统保存的是可以独立编辑、核验、重组和投影到交付物的对象。

对象模型需要同时满足：

1. 首版能够支持一次P-001售前研究；
2. 不要求用户手工维护复杂知识图谱；
3. 未来可以增加画布、看板、团队协作和 Agent，而不改写基本事实结构；
4. 事实、推断、假设、模型建议和人工决定不能因项目推进而混为一类。

## 2. 当前最小追溯链

```text
Project / Brief
      ↓
ResearchQuestion
      ↓
Source → EvidenceExcerpt → Claim
                              ↓
                      Finding / Option
                              ↓
                      DeliverableBlock
                              ↓
               ReviewDecision / OverrideDecision
```

### 2.1 为什么新增 Claim

EvidenceExcerpt 是来源中的原文或数据位置，Claim 是系统或顾问从中提出的一条可独立检查的主张。

例如：

```text
Source：某份市场报告
EvidenceExcerpt：第 12 页的一句话或表格单元格
Claim：2024 年某市场规模为 X，地域和统计口径为 Y
```

一段来源可能支持多个 Claim，一个 Claim 也可能由多个来源支持或反驳。Finding 则是在多个 Claim 基础上的综合解释。

没有 Claim 层，来源摘录、事实主张和分析结论容易被合并成一整段不可核验的 AI 文字。

## 3. P0 对象定义

### 3.1 Project

- 项目名称；
- 当前采用的 ProjectTemplate / AnalysisModule 配置；
- 当前执行配置；P0 固定为P-001结构化研究 Workflow，不把“快速/完整”做成封闭枚举；
- 当前版本和状态；
- 创建人、时间和材料范围。

### 3.2 Brief

- 用户原话；
- 可能需要做出的决定；
- 对象、地域、时间和范围；
- 受众和本轮交付物；
- 已知、假设和未知；
- 人工确认或修改版本。

### 3.3 ResearchQuestion

- 要回答的问题；
- 为什么影响当前决策；
- 所需证据或分析；
- 优先级；
- 暂时够用条件；
- 当前状态：未开始、研究中、待补料、暂时够用、受质疑、已替代。

P0 不要求把 ResearchQuestion 建成复杂任务管理系统。

### 3.4 Source

统一表示网页、文件、数据、访谈和人工输入：

- 类型；
- 原始 URL 或文件；
- 标题、作者/机构、发布日期和访问时间；
- 权限、敏感性和可访问状态；
- 项目内快照或受控副本、文件哈希和原始路径；
- 原始来源、二手来源、聚合/摘要、用户材料或访谈的分类。

搜索结果先作为 CandidateSource，经过打开和定位后才成为可引用 Source。

Source 可访问状态至少包含：`available`、`path_expired`、`permission_denied`、`deleted`。导入不能只记录微信缓存或用户设备上的临时路径；来源失效后不得假装仍可核验，但已保存的历史摘录也不应被静默删除。

### 3.5 EvidenceExcerpt

- Source ID；
- 精确原文、表格值或图片区域；
- 页码、工作表/单元格、网页位置或图片坐标；
- 时间、地域、单位和统计口径；
- 与上下文有关的限制。

### 3.6 Claim

- 原子主张；
- 认识类型：事实主张、推断、假设或顾问判断；
- 支持和反驳的 EvidenceExcerpt；
- 核验状态；
- 适用范围和时间；
- 是否允许进入当前交付版本。

Claim 核验状态：

- captured；
- source_checked；
- corroborated；
- conflicted；
- stale；
- unverifiable；
- excluded。

事实主张表示“来源声称了什么”，不等于系统确认现实一定如此。二次成果页中的事实文字可以处于 `captured`，但在找到原始来源或独立证据前不能升级为 `corroborated`。

### 3.7 ModelSuggestion

模型训练记忆或模型自行提出、但没有可定位来源的内容。

它不是 Source、Evidence 或已核实 Claim。它只能：

- 生成搜索词；
- 提出研究问题；
- 形成待验证假设候选；
- 提醒可能遗漏的替代解释。

如果后续找到来源，可由来源生成新的 EvidenceExcerpt 和 Claim；不得直接把 ModelSuggestion 升级成证据。

### 3.8 Finding

- Observation：Claim 显示什么；
- Interpretation：为什么可能如此；
- Alternative：替代解释；
- Implication：对决策的意义；
- Evidence for / against；
- Gap；
- 人工评审状态。

### 3.9 Option

探索型项目按需使用：

- 候选方向；
- 作用机制；
- 所依赖的 Finding 和 Claim；
- 适用前提；
- 反证和淘汰条件；
- 下一最小验证动作；
- 当前状态：候选、待补证、保留、暂缓或排除。

专题研究可以没有 Option，不应为了完整流程强制生成策略方案。

### 3.10 DeliverableBlock

- 备忘录的一段或 PPT 的一页；
- 所引用的 Claim / Finding / Option；
- 对外或对内状态；
- 假设、冲突和限制提示；
- 人工修改版本。

### 3.11 ReviewDecision

- 批准、修改或否决；
- 作用对象；
- 操作者、时间和理由；
- 是否允许进入下一交付版本。

### 3.12 OverrideDecision

- 目标决策门或交付版本；
- 按假设、排除或情景推进；
- 推进人、时间和理由；
- 受影响对象；
- 重审条件。

OverrideDecision 改变进度，不改变 Claim 的核验状态。

## 4. 数据与分析对象

P0 不建设完整模型引擎，但数据计算必须可追溯：

```text
Dataset / Source
→ 字段与口径
→ 清洗或计算步骤
→ AnalysisArtifact
→ Claim
```

AnalysisArtifact 可以是：

- 清洗后的表格；
- 竞品对比；
- 简单计算；
- 图表；
- 地图或空间分析结果；
- 未来的财务或情景模型输出。

必须保存输入、计算方法和输出位置，不能只写“由 AI 分析得到”。

## 5. 工作深度预设与项目类型的边界

“轻量研究”和“结构化项目”只是早期用于解释交互深度的两个预设示例，不是经纬对咨询课题的永久分类，也不是核心 schema 中只能二选一的 `mode`。未来工作台可以根据项目模板、分析模块、执行策略和视图组合形成更多工作形态，而不改写 Source—Claim—Finding—Deliverable 主链。

P0 只实现P-001低信息售前研究所需的结构化研究闭环。轻量研究预设用于未来迁移测试和架构扩展演练，不进入当前页面、流程分支或验收范围。

### 5.1 轻量研究预设（未来示例）

用于 benchmark、案例搜集和一句话专题研究：

```text
Brief
→ 最小 ResearchQuestion
→ Source / Claim
→ Finding
→ DeliverableBlock
→ Review
```

不要求启用完整画布、Option、看板和决策门。

### 5.2 结构化项目预设（P0 只实现P-001所需部分）

用于P-001等探索型售前或策略项目：

```text
Brief / Decision
→ 多个 ResearchQuestion
→ Source / Claim / AnalysisArtifact
→ Findings
→ Options
→ DeliverableBlocks
→ Review / Override
```

P0 不因此实现完整项目管理。后续只有在P-001闭环验证成立后，才可以在同一对象底盘上增加画布、简化看板和其他工作形态。

## 6. 画布、看板和故事线如何复用对象

| 视图 | 主要显示对象 | 不应另建的重复状态 |
|---|---|---|
| 咨询项目画布 | Brief、ResearchQuestion、Finding、Option、Review | 不复制来源和任务正文 |
| 研究执行看板 | ResearchQuestion / 后续 ResearchTask、阻塞和负责人 | 不重新维护一套结论 |
| 交付故事线 | DeliverableBlock 及其 Claim / Finding 引用 | 不复制一份无法回溯的 PPT 文本 |

视图只是对同一对象的投影。

## 7. 后续扩展对象

仅在相应场景得到验证后增加：

| 对象 | 场景 |
|---|---|
| ResearchTask / WorkPacket | 多人协作和执行看板 |
| ImpactLink | 复杂依赖和跨项目影响分析 |
| Schedule / Snapshot | 定期情报和月报 |
| Interview / Participant / Consent | 正式访谈管理 |
| Model / Scenario | 财务、市场和空间情景 |
| Initiative / Owner / KPI | 实施与 PMO，可能属于独立模块 |
| Organization / Role / Permission | 团队或企业版本 |
| AgentRun / ToolPermission / Budget | 受限 Agent 编排 |

### 7.1 扩展接缝

未来能力通过接缝增加，不修改 P0 主链的含义：

```text
项目类型 → ProjectTemplate / AnalysisModule
材料类型 → SourceAdapter / Parser
分析方法 → AnalysisArtifact
执行方式 → Human / Workflow / Agent ExecutionStrategy
交付格式 → DeliverableExporter
界面形态 → 同一对象的 View Projection
```

这些名称是技术设计约束，不是要求 P0 立即实现插件系统。P0 只需保证P-001代码不把“冷链、区位、产业链、东方甄选”写入核心对象字段或通用状态机。

### 7.2 版本与迁移

- Project 和对象样本记录 `schema_version`；
- 核心对象字段变更必须提供显式迁移；
- 不使用一个无约束的 JSON `metadata` 长期承载全部未来需求；
- 新模板可以增加配置和专业 AnalysisArtifact，但不得复制 Source、Claim、Review 和版本系统；
- 内部对象 ID 用于追溯，默认不直接展示给普通用户。

## 8. 认识状态与项目进度分离

三个维度不能混在一个 status 字段中：

1. **研究进度**：未开始、进行中、暂时够用、待补料；
2. **认识状态**：事实主张、推断、假设、判断及核验状态；
3. **交付状态**：草稿、内部评审、售前版本、对外批准。

因此以下状态是合法的：

> 一个项目已进入售前版本，但其中两条 Claim 仍是 unverifiable，并通过 OverrideDecision 以假设方式保留。

## 9. 对地产产业模板的映射

P-001模板可以推荐：

1. 项目本体与经营；
2. 区位、市场与竞争；
3. 产业与需求；
4. 客群、生态与产业链；
5. 政策与案例；
6. 策略选项；
7. 可行性与优先级。

这些是 ResearchQuestion / analysis module 模板，不是底层对象，也不是所有咨询项目必须通过的步骤。

## 10. 质量不变量

- 任一事实性 DeliverableBlock 可以回到具体 Claim 和 EvidenceExcerpt；
- 推断必须显示其依据和替代解释；
- 模型建议不得伪装成 Source；
- 用户强制推进不得改变核验状态；
- 新材料不得静默覆盖人工修改；
- 同一对象在画布、看板和故事线中只保存一次；
- 没有数据时允许“不知道”，不生成伪精确评分；
- 用户不需要为了追溯性重复录入已经能够自动获得的元数据。
