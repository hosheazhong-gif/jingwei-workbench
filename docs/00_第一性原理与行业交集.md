# 第一性原理与行业交集

## 1. 第一性原理：咨询究竟在生产什么

咨询的最终产品不是报告、PPT、模型或“行业知识”，而是：

> 在时间有限、信息不完整、利益相关方不同的条件下，帮助客户提高一项重要决策的质量，并降低执行这项决策的阻力。

因此，一项咨询工作的最小闭环是：

1. 明确客户真正需要做出的决定；
2. 把模糊问题拆成可验证的问题和假设；
3. 找到足以改变决策的证据；
4. 用定性和定量分析检验假设；
5. 将事实综合为少量洞察和可比较选项；
6. 给出带条件、风险和影响的建议；
7. 通过沟通、研讨和实施安排推动行动；
8. 根据新信息和执行反馈调整判断。

PPT、Excel、访谈纪要、报告和工作坊只是承载这个闭环的媒介。

## 3. 共同工作流与差异化分析模块

### 3.1 跨项目稳定的“经”

```text
Mandate 任务与决策
  → Frame 问题结构化
  → Plan 证据与分析计划
  → Build 研究、访谈与模型
  → Test 检验假设
  → Synthesize 综合洞察
  → Choose 形成和比较选项
  → Deliver 沟通建议
  → Activate 实施与复盘
```

这条纵向流程适合成为系统导航、项目状态和权限审批的主骨架。

### 3.2 按需装配的“纬”

不同项目只是在横向选择不同分析模块：

- 外部环境：宏观、政策、技术、社会、情景；
- 市场：规模、增速、细分、需求驱动、进入壁垒；
- 客户：细分、需求、旅程、支付意愿、流失与终身价值；
- 竞争：对标、份额、能力、商业模式和相对定位；
- 经济性：收入池、成本、利润、资本需求、敏感性；
- 内部能力：资源、流程、组织、技术、治理；
- 价值链与生态：参与者、权力、利润池、依赖和合作；
- 空间与区位：可达性、客流、供需、网络、设施和场景；
- 方案与执行：选项、优先级、路线图、责任、指标和风险。

不应要求每个项目都把这些模块跑一遍。系统应根据决策问题和项目模板推荐最小充分分析集，再由顾问确认。

## 4. 对原七层框架的审计

原框架：产业识别、政策层、产业分析层、产业图谱、产业链分析、本地基础层、延链机会层。

### 4.1 值得保留的内容

- 先辨认概念与边界，避免研究对象漂移；
- 把政策、行业、生态、本地条件和机会连接起来；
- 对地产和区域产业策划具有较强业务适配性；
- 强调信息缺口、来源和机会证据等级。

### 4.2 不适合作为通用主骨架的原因

1. **把分析维度误当成项目步骤**：政策、产业链、本地基础可以并行，不一定按顺序发生。
2. **产业图谱与产业链重叠**：参与者、上下游、生态关系和价值分配边界不清。
3. **缺少客户和商业经济性**：多数增长、定价和商业战略都需要客户、收入、成本和利润分析。
4. **缺少内部视角**：公司战略与转型必须判断组织、流程、能力和资源。
5. **从分析直接跳到延链机会**：缺少决策标准、选项比较、风险、投资和实施路径。
6. **本地基础过于地产化**：它适用于区位、园区和公共部门项目，不适用于所有战略问题。
7. **没有项目管理和交付闭环**：访谈、工作坊、版本、批注、数字校验、PPT 和实施没有进入模型。

### 4.3 重构后的地产/产业策略模板

七层不再是产品导航，而成为一个可选择的模板包：

1. 产业定义与决策边界；
2. 外部环境与情景；
3. 市场、客户与需求；
4. 竞争、价值链与生态；
5. 本地资源、空间条件与内部能力；
6. 机会选项、经济性和风险比较；
7. 定位、路线图、实施主体和验证指标。

原来的政策、图谱、产业链和本地基础会作为证据和分析模块嵌入这些阶段，而不是僵硬地逐层生成七份文字。

## 5. 经纬不应变成什么

- 不做无项目上下文的万能问答机器人；
- 不以生成长篇行业概览作为成功；
- 不自动替客户作最终战略选择；
- 不把未经验证的网页摘要写成事实；
- 不因为想覆盖 MBB/四大，就同时开发所有策略模板；
- 不以“像某家咨询公司内部系统”为卖点。

## 6. 新产品的核心判断

经纬的差异化不是拥有最多咨询框架，而是：

> 让一个结论能够向下追溯到证据和分析，向上连接到客户决策、交付页面和实施动作。

这比“七层报告生成”更贴近不同策略咨询团队的共同工作，也保留了地产与空间策略可沉淀、可验证的优势。
