# 对话结论与产品类型决策

> 记录日期：2026-08-11  
> 更新日期：2026-08-12  
> 状态：关键概念决策记录；具体范围以 PRD v0.4 为准  
> 用途：把此前关于 Prompt、Workflow、Agent、Harness、低数据售前和咨询共性的讨论从聊天迁入项目记录。

## 1. 当前结论

经纬当前应被定义为：

> 面向咨询研究与售前分析的人机协作 AI Workflow 应用。

它不是单轮 Prompt 工具，也不以“多 Agent”作为首版目标。产品价值来自把一个咨询任务持续保存为项目状态，并让搜索、人工补料、证据核验、分析、写作、评审和返工发生在同一条可追溯工作流中。

这里需要区分两层：长期愿景是“咨询证据到决策工作台”；当前 MVP 只验证地产/产业咨询中的低信息售前研究闭环。完整画布、团队看板和交付故事线是后续形态，不代表首版同时开发。

## 2. 已纠正的前提

### 2.1 “用了 Prompt 就只是 Prompt 项目”不成立

Prompt 是模型调用的一种实现手段，不是产品分类。若系统只能接收一次输入并返回一次文本，它接近 Prompt Wrapper；若系统还保存任务、材料、来源、证据、假设、版本和人工决策，并能在失败或补料后继续推进，它已经是 Workflow 应用。

### 2.2 “数据不足就无法做咨询工具”不成立

真实咨询经常从一句客户需求、一个地点或少量旧材料开始。产品不能把“缺数据”当作异常，而应输出：

- 已知事实；
- 明示假设；
- 关键未知项；
- 初步研究方向；
- 数据请求和访谈计划；
- 仅供讨论的初步假设，而非最终建议。

### 2.3 “AI 找不到就代表流程失败”不成立

人可以在任意阶段补充文件、数据库导出、访谈纪要、网页线索或人工判断。系统的完成标准不是 AI 独立做完全部工作，而是项目在 AI 与人交替工作后仍能保持状态、来源和版本连续。

### 2.4 “接入搜索、生成和多个工具就一定是 Agent”不成立

固定步骤调用搜索、解析和模型属于 AI Workflow。只有当系统能围绕目标动态拆解任务、选择工具、根据结果调整下一步并在边界内循环执行，才具有明显 Agentic 特征。多个工具的接入层可以是 Harness，但 Harness 是技术底座，不应直接作为产品卖点。

## 3. 产品类型边界

| 分类 | 经纬 MVP 是否属于 | 说明 |
|---|---:|---|
| Prompt Wrapper | 否 | Prompt 只是局部实现，项目状态不依赖单次对话 |
| 问答机器人 | 否 | 聊天是入口之一，不是信息架构本身 |
| 普通效率工具 | 部分 | 包含搜索、摘录、整理、核验和写作效率功能 |
| AI Workflow | 是 | 固定主流程、持久化状态、人工确认和失败恢复 |
| Agentic Workflow | 后续候选 | 只有验证出适合自动决策的环节后再增加 |
| Multi-Agent | MVP 不做 | 当前没有证据证明多角色 Agent 比单一编排流程更有效 |
| Harness | 可能是技术实现 | 若统一管理模型、搜索、文件、任务、权限和日志，可称轻量 Harness；不等于产品本身是 Agent |

## 4. 咨询共性与经纬锚点

跨地产、产业、企业战略、增长、运营转型和数字化咨询，稳定交集不是某套七层框架，而是：

```text
模糊任务
→ 明确决策与范围
→ 拆问题和假设
→ 制定证据计划
→ 搜索 + 客户材料 + 访谈 + 数据分析
→ 核验和综合
→ 形成选项、建议与不确定性
→ 生成内部讨论材料
→ 人工评审和返工
```

经纬不以覆盖所有咨询模板为首要目标。首版仍以用户有真实经验的地产、产业、区位和商业研究任务作为锚点，但底层对象使用可跨项目复用的 Brief、ResearchQuestion、Source、EvidenceExcerpt、Claim、Finding、Option、DeliverableBlock 和 ReviewDecision。

## 5. 验证场景及顺序

### 第一验证场景：低信息售前

输入：“华南某镇一处冷链仓大部分已由某仓储会员店使用，剩余约三分之一空间应该做什么？”以及场地位置。

验证系统能否在不虚构面积、租金和需求的情况下，完成公开信息初查、竞品/案例线索、机会假设、反证、客户问题、数据请求和 proposal storyline。

### 第二迁移测试：专题研究

输入：“头部券商公司有哪些降本增效方法？”以及用户后来补充的材料。

验证系统能否把搜索结果和人工文件统一整理、去重、核实来源、区分公司事实与通用推断，并生成带引用的内部研究报告大纲。

### 后续回归测试：重复型月报

产业园月报保留为后续回归案例，用于验证多期数据标准化、变化识别和重复更新效率，不再与首个 MVP 争夺优先级。

## 6. 已确认的范围决定

- 首版实现单一人机协作 Workflow，不实现多 Agent 团队；
- 首轮只用P-001 冷链园区验证最小闭环，不同时实现三个场景；
- 人可以随时暂停、补料、编辑、否决、回退和继续；
- 系统可搜索公开网页，但不承诺获取付费数据库、企业内网或不公开情报；
- 客户/内部材料主要由用户上传或粘贴，系统负责解析、整理和溯源；
- 所有重要数字与结论必须保留来源、日期、口径和认识状态；
- 信息不足时输出假设和研究计划，不伪造确定结论；
- 首版交付可编辑的内部可审查材料，不自动生成可直接发给客户的最终方案；
- Source、EvidenceExcerpt、Claim 与 DeliverableBlock 构成首版最小追溯链；
- 完整画布、团队看板和故事线属于后续个人/团队工作台路线，不属于 P0 完成条件；
- Case 面试训练是研究附录，不进入 MVP；
- 数字化、商业尽调、PMO 等保留为未来模板，不在首版同时开发。

## 7. 仍需后续交互、但不阻塞 PRD 的事项

1. **首个实测材料**：冷链、券商研究和产业园月报分别能提供到什么程度；
2. **首版交付格式**：内部 Markdown/Word 研究备忘录、PPT storyline，还是必须生成可编辑 PPT；
3. **部署与隐私**：本地优先桌面端、浏览器本地应用，还是允许云端项目空间；
4. **公开搜索范围**：优先搜索哪些网站、政府平台、公司公告和行业来源；
5. **评价基线**：选择一轮过去的人工成果，用于比较普通聊天、原人工流程和经纬 Workflow。

这些问题应在原型和真实材料测试中回答，不应继续仅凭想象扩写功能。
