# P-001可运行界面真人测试脚本

> 2026-08-14 产品所有者裁决：不再执行本走查，下一刀改为空白题目创建（已实现）。本文件保留脚本原文，记录表仍空。  
> 历史原型脚本：[P-001 P0 状态变化任务测试脚本](16_P-001_P0状态变化任务测试脚本.md) 仍只适用于 v0.3 原型

## 1. 测试前只给测试者这一句

不解释 Source、Claim、OverrideDecision 等内部术语：

> 经理准备看内部稿。请先确认「项目问题」里客户说的食品客群占比现在能不能写、为什么；冷链市场数据附件打不开，请处理这份材料，再补入替代文件，判断哪些内容要重审，最后导出 Word 看还要不要大改。

替代文件是 `samples/case-p001/replacement_macro.txt`。它只用于保存、哈希、影响提示和重审，**不含已核验市场数值**。若内部稿或导出里出现 `FAKE_GDP_9999`，本轮失败。

## 2. 主持人准备（测试者开始前完成）

在项目根目录：

```powershell
py -3.12 -m unittest discover -s tests -v
```

若 `var\jingwei-demo.sqlite3` 已存在且不是干净样本，先移走再导入：

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\demo_windows.ps1
PowerShell -ExecutionPolicy Bypass -File .\scripts\serve_readonly.ps1
```

浏览器打开：

```text
http://127.0.0.1:8000/?project=P-QH-001
```

准备好秒表。记录开始时刻。不要提示段落名称或技术编号。

## 3. 测试者独立完成

1. 打开内部稿，点「项目问题」。说明客户提供的食品客群占比现在能不能写、为什么、来自哪里。
2. 点「本轮任务」，用一句话说清当前要支持的决策和本轮交付。返回内部稿。
3. 在「项目问题」上做一次「按假设推进」。读屏幕上的处理结果：创建了什么、作用于哪一段、什么没有改变。
4. 点「补充材料」。路径填写项目内的 `samples/case-p001/replacement_macro.txt`（或该文件的本机绝对路径），名称可写「替代宏观市场材料」，替代已有材料选「中国冷链市场总产值数据（文件路径已失效）」，保存。
5. 查看补料后的影响范围。说明哪些判断或段落需要重审；内部稿正文有没有被改写。
6. 任选其一：对某一段「从本版排除」，或退回修改但**不**点采用候选。
7. 导出 Word，用 Word 打开，判断还要不要大段重排或重贴。
8. 关掉标签页，再打开同一地址，看刚才的处理和材料是否还在。

记录结束时刻、操作次数（推进、排除、修改、补料、导出各几次）。

## 4. 不要用原型文案当标准答案

可运行样本里，失效宏观材料的显式影响是判断「当前最严重的问题是证据链断裂，而不仅是信息量不足」，**没有**名为「行业前景与市场表现」的段落。宏观材料不能单独证明项目需求。测试者说「没有市场规模段落 / 只有证据链断裂」是符合不变量，不是失败。

## 5. 测试后只问这些

1. 新材料加入后，哪些内容需要重审？
2. 为什么新文件已经可打开，市场数字仍不能直接写入？
3. 带风险推进改变了什么，没有改变什么？
4. 如果改用普通聊天，你需要自行记住或重新核对哪些内容？
5. 导出的 Word 还要改多少？是改结论、改口径，还是改排版？
6. 这一套操作的返工收益，是否值得其理解与维护成本？
7. 下一个真实任务还愿意用吗？

## 6. 通过条件

必须同时满足：

- 能说明客户提供信息可以带归属写入，且未独立核实 / 口径待补仍在；
- 不把「文件可访问」当成「数字已核验」；
- 理解带风险推进改变本版处理，不改变证据核验状态，也不自动改内部稿；
- 补料后能指出系统给出的影响范围，且内部稿没有出现种植数字；
- 能在不重新生成整份报告的情况下完成局部处理；
- 能说出相对聊天减少的恢复或返工动作，而不只是评价界面清不清晰；
- 能对 Word 返工给出具体判断（几乎不用改 / 还要大改排版 / 还要重写结论）。

第 7 题「下一个任务还愿意用吗」记录原话，不因这一题单独判定整轮失败。

## 8. 失败后的处理

- 看不懂状态：先改措辞与反馈，不增加新功能；
- 能理解但明显繁琐：减少要维护的对象和状态；
- 说不出相对聊天的返工收益：不进入画布、看板或 Agent；
- 不因失败增加券商、机场、轻量研究入口、完整工作台或 Agent。
