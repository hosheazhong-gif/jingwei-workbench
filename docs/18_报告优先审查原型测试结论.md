# 报告优先审查原型测试结论

> 日期：2026-08-12  
> 对照对象：四工作区原型 v0.3 与报告优先审查原型  
> 结论：报告优先方案通过本轮理解门槛，可以进入最小技术架构设计

## 1. 用户反馈

用户在补入替代材料后，能够直接说出：

> 新材料影响的内容已经说出来了，行业背景判断和行业前景与市场表现，然后等我重新审核，现在很明确了。

这次回答同时命中了三个关键点：

1. 系统主动指出受影响内容，不要求用户自己恢复依赖关系；
2. 影响落在自然语言的“判断”和“报告段落”，而不是技术对象编号；
3. 系统等待人工局部重审，没有自动覆盖旧稿或把新文件当成已核实事实。

## 2. 第一性原理判断

顾问的直接任务是修改和交付材料，不是维护一张对象图。Source、Claim、Finding、DeliverableBlock 仍然必要，但它们应当负责保存和计算，不应成为 P0 默认导航。

报告优先界面把结构化成本藏在底层，只在用户需要判断时回答四件事：

1. 这段现在能不能写；
2. 为什么；
3. 来自哪里；
4. 新材料加入后哪里需要重审。

这比四工作区原型更接近真实工作，也第一次给出了相对普通聊天的明确价值信号：系统替用户保存并恢复影响范围。

## 3. 强制分类

### P0 必需修正

- 报告优先审查界面成为P-001 P0 默认入口；
- 客户来源、核验限制、引用回跳和风险处理显示在相关段落旁；
- 补料影响直接用判断名称和报告段落名称表达；
- 底层仍保存 Source—EvidenceExcerpt—Claim—Finding/Option—DeliverableBlock，不复制状态。

### 后续验证假设

- 独立 Source/Claim 研究工作区只作为复杂任务的深度视图候选；
- 四工作区可能成为未来结构化项目预设，而不是 P0 默认首页；
- 画布、看板和故事线仍属于后续同一对象多视图。

### 不做

- 不增加券商、机场、轻量研究入口、完整工作台或 Agent；
- 不因界面收缩删除底层追溯、版本、评审和扩展接缝。

## 4. 本轮通过边界

通过的是“界面理解门槛”，不是整个产品假设。仍需可运行纵向闭环验证：

- 实际文件能否生成快照、哈希和精确定位；
- 新材料能否稳定计算有限影响范围；
- 人工编辑和评审能否跨重新生成保留；
- 可编辑导出是否减少重新复制；
- 相比普通聊天是否减少真实返工和上下文恢复时间。

因此下一步是最小技术架构和扩展接缝，不是扩展业务场景。
