# PRD v0.5｜经纬：低信息售前写稿工作台

> 状态：当前产品与 MVP 基线；P0 已由产品所有者于 2026-08-19 收口；同日走查后追加第 20.1、20.2 节  
> 日期：2026-08-16（收口附记 2026-08-19）  
> 替代关系：替代 [v0.4](01_PRD_v0.4.md) 作为当前基线；v0.4 保留审查两栏阶段的完整规格  
> 当前产品类型：人机协作写稿循环（外圈循环 + 账本内核），不是聊天成稿，也不是 Agent 产品  
> 长期愿景：咨询证据到决策工作台  
> P1：第一刀已授权并开工——按经理原话拆本轮问题（模型先拟、人收下）。画布、无人值守 Agent、第二业务仍按第 19 节不做。

## 1. 本版做出的关键修正

1. **换产品面，留账本内核。** v0.4 默认的「内部稿 + 审查侧栏」已证明补不回工作台初衷，停止打磨。对象链、测试、导出不从零重写。
2. **默认界面改为一块工作台同时三件事：** 本轮问题进度、中间一篇给经理的稿、旁边材料匣。
3. **模型写的是稿上的一节**，人预览后收下、改完收下、或丢掉。空白题允许写缺口稿，不得发明统计数字。
4. **进度只用本轮问题的三档：** 还没写 / 草稿 / 这轮够用了。核验枚举退出主操作，仍写入账本。
5. **无来源数字标红，人仍可收下**；红字跟着稿和导出走，收下不等于已核实。
6. **机械检查不是模型给自己打分。** 至少检查：无来源数字、稿里新冒出的主张、客户口头被写成已核实、宏观被用来证明项目需求；补料后已收下的节能标过时。
7. **交互原则进入 P0：** 层次靠点击展开，默认少按键、少下拉、少文本框。不是再给旧审查页换皮。
8. 长期仍建设咨询工作台，但首版不同时实现完整画布、团队看板、企业知识库和多 Agent。

## 2. 长期愿景与当前承诺

### 2.1 长期愿景

> 经纬成为咨询与内部战略团队的证据到决策工作台：把任务、来源、主张、分析、选项、交付和人工决定保存在同一个可追溯项目中，并支持团队协作、重复更新和受限 Agent 执行。

愿景仍保留画布、看板和故事线，作为同一对象的未来投影，不进入本版完成标准。

### 2.2 当前 MVP 承诺

> 帮助一名地产或产业咨询顾问，在材料不全时，在一块工作台里看见本轮要决定什么、让模型加快写出给经理的稿、材料始终在手边；系统不把没来源的数字装成已核实，也不覆盖旧材料。

首版不承诺管理整个咨询项目，也不承诺替代最终的 PowerPoint、Excel、访谈、专业数据库和经理判断。

### 2.3 架构原则

```text
愿景上保留工作台
→ 对象模型不封死未来扩展
→ 当前只实现一块写稿工作台 + 账本内核
→ 后续阶段必须由真实验证触发
```

## 3. 第一性原理下的产品问题

### 3.1 用户不是为了维护框架而工作

咨询生产的不是报告、PPT 或「行业知识」，而是：在时间有限、信息不完整时，提高一项决策的质量。报告只是媒介。

顾问真正要完成的是：交出一份经理能继续判断、修改和对客沟通的材料。工具只有在降低搜索、复制、核对、返工和恢复上下文的成本时才成立。维护主张状态的时间一旦大于减少的返工，产品就失败——v0.4 审查面已经撞上这条。

### 3.2 当前真实替代方案

- 网页搜索、企业官网、政府网站和专业数据库；
- ChatGPT、Deep Research、NotebookLM、Notion Research 等通用 AI；
- Word、PowerPoint、Excel、微信/邮件和共享文件夹；
- 经理经验、旧项目模板和同事口头指导。

因此经纬不能仅以「生成更完整报告」为价值。稿填满了若不能让经理更清楚「这轮要决定什么」，产品仍不成立。

### 3.3 当前核心痛点假设

1. 搜过什么、为何保留或排除难以恢复；
2. 来源原文、事实主张、AI 推断和顾问选择容易混在一起；
3. 新材料出现后，不知道哪些结论和页面需要重新检查；
4. 普通对话能生成文字，但难以稳定承接多轮补料和经理返工；
5. 信息不足时，工具容易阻塞或给出伪确定性结论；
6. 做成审查账本后，人看不清进度，模型也加快不了写稿。

这些仍是待验证的产品假设。第 6 条已被本机自测部分证实，本版转向写稿工作台来再验。

## 4. 核心用户、使用时刻与购买边界

### 4.1 首要操作者

- 地产、产业、区位和商业策略团队的 Analyst / Consultant；
- 接收经理的一句话任务并负责 desk research、案例、数据整理和初稿的人；
- 当前首先服务产品所有者本人能够还原和测试的真实工作。

### 4.2 下游评审者

- Manager / Project Lead；
- 首版通过可编辑 Word 参与，不要求建设完整经理端和组织权限。

### 4.3 当前使用时刻

```text
经理发来一句模糊任务
→ 用户需要在有限时间内形成第一版研究与讨论材料
→ 客户详细资料可能尚未提供
→ 后续仍会补料、改方向或删除部分结论
```

### 4.4 暂不解决的购买问题

首版是产品发现与作品集 MVP，不假设已经获得咨询公司的企业采购。

## 5. 核心 Job to Be Done

> 当我收到定义不清、时间紧、材料不完整的咨询研究任务时，帮助我在一块台面上看见本轮要决定什么和还要回答哪些问题，让模型写出可收下的一节给经理的稿，材料始终在手边；即使资料不足也能写缺口稿并带风险交给经理，同时系统不会把未核实内容伪装成事实。

## 6. MVP 最小闭环

### M1｜创建研究任务

输入允许为：一句话；一句话 + 地点；一句话 + 文件/图片/网页；一批材料但问题尚未完全明确。

系统形成一张可编辑 Brief：原始委托、可能需要做出的决定、当前范围和受众、已知/假设/未知、本轮最小交付物。用户可以直接修改，也可以在未完全确认时继续。

**工作台顶上始终能看见本轮要决定的那句话。** 本轮问题是它的拆解，不是报告目录。

### M2｜形成最小研究计划

系统只生成足以支持本轮交付的研究问题，不自动展开完整咨询框架。每项问题包含：为什么影响当前决策、需要什么材料、何时「暂时够用」。

界面进度只显示三档，由人点：

- **还没写**：还没有一段能看的字；
- **草稿**：有字，人还没点头；
- **这轮够用了**：人认为可以拿去跟经理讨论这一块。

「够用了」表示可以讨论，不表示散文写完，也不改变主张核验状态。P-001模板可以推荐若干问题，用户不必全部启用。

### M3｜搜索与材料进入材料匣

材料类型包括网页、PDF、Word、Excel、PPT、图片、访谈纪要和人工录入。所有搜索结果先进入 CandidateSource，不自动成为证据。未打开的网页不能当依据。

仅保存外部路径不算完成导入。新材料创建新 Source，不覆盖旧文件、旧哈希。来源失效时保留历史摘录，并标出已收下、受影响的稿节为过时。

**材料必须看得出对应哪一轮的哪条问题。** 搜到的候选和升上来的来源都挂在点开的那条本轮问题上；本轮收口后，旧材料仍显示成「第 N 轮 · 那条问题」，不得退回成「还没标对应哪条问题」。旧材料的问题字段为空时由人补标，系统不猜填。

**存下了受控副本不等于存下了正文。** 抽不出正文的快照不提供「看快照 / 从快照扒原话」，卡片直接说明只能打开原链接，不让人点下去才发现是死路。

### M4｜形成证据摘录与原子主张

内核仍是：

```text
Source → 精确摘录 → 一条可以独立检查的 Claim → 认识类型和核验状态
```

认识类型仍为事实陈述 / 推断 / 假设 / 判断。模型训练记忆不是来源。这些字段默认不对用户摊成表单。

### M5｜综合发现与候选方向

Finding 与 Option 仍写入账本。默认工作台不把「写下总判断 / 可试方向」做成主路径按钮；它们随一节稿被收下而挂上，或留在技术详情。

### M6｜给经理的稿

**稿要按材料的信息量写，不是压成概述。** 材料给了清单、年份、金额、比例、地区、企业名、文件名，就逐条写出来，不合并成「等」；内容多时用小标题分小节、同类事实分条罗列，让经理能扫读。压缩比不是目标——把 5000 字材料写成 900 字三段白话，等于把经理要的东西丢了。

**给经理的这一篇是内部整理稿，不是给客户的交付物。** 它要能当工作底稿读：论文式小标题单独占行，并列事实以「1. 2. 3.」分条各占一行，每条至少一个完整句子并带上出处名称，结尾另起「小结」说这一节答到哪一步、还差什么。不许整节只写一两句话，也不许用「综上所述」凑段。给客户的稿是另一件事，不在本版。

**导出两份，读的是同一份批准投影。** 经理版（`word` / `markdown`）以生成的正文为主体，来源只列名称加链接或文件名；主张全文不复述进导出，但「客户提供」「未独立核实」两个标记必须跟着来源走。详细版（`word_detailed` / `markdown_detailed`）另加过程：逐节列出支撑这一节的每条主张、主张背后的原文摘录、来源与限制、机械检查结果、这一节是第几轮第几版。两份用同一批段落 id，详细版不产生第二套结论。

中间那篇就是以后导出的 Word。模型写的是这里的一节；人收下后才算进稿。沿用既有段落版本（先有候选，确认后替换当前正文），不新造第二套正文。

空白题不再用「系统不会代写」堵死模型。没有材料时写缺口稿（还缺什么、客户口头怎么带归属写），不能发明统计数字。

### M7｜检查、补料和继续

外圈循环：

```text
人选定一节或一条本轮问题
→ 系统装入：本轮决定、该问题、现稿、已有摘录
→ 模型写出这一节候选
→ 另一个检查（不是模型给自己打分）
→ 人收下、改完收下、或丢掉
→ 人点「这轮够用了」或继续下一节
→ 导出 Word
```

机械检查至少包括：

1. 数字、机构名若无来源，标红；
2. 写成稿时新冒出来的主张，标出来；
3. 客户口头被写成已核实，标出来；
4. 宏观材料被用来证明项目需求，标出来；
5. 补料后，已收下且受影响的节标过时。**新挂上原话也算补料**：一节收下之后又挂了原话，要在那一节上说出来，否则人挂完材料看不出稿该动。

标红可收下。红字跟着进稿、跟着导出。收下不等于核验升级，也不等于外部独立核实。点标红句子，材料匣翻到出处；没有出处就停在「未挂来源」。

## 7. 人工强制推进

资料缺失、售前或时间紧迫时，人可以在稿里收下缺口稿，并把对应问题标成「这轮够用了」。系统记录带风险推进，不改变主张核验状态。

强制推进不再作为主按钮出现。可选处理（按假设、从本版排除、按情景表达）留在账本，默认不做成一排键。

## 8. 统一对象模型

对象集合与 v0.4 相同，不从零重写。

### 8.1 P0 必需对象

Project、Brief、ResearchQuestion、Source、EvidenceExcerpt、Claim、Finding、Option、DeliverableBlock、ReviewDecision、OverrideDecision、ModelSuggestion。

### 8.2 最小追溯链

```text
Source → EvidenceExcerpt → Claim → Finding / Option → DeliverableBlock
                                      ↓
                              Review / OverrideDecision
```

新视图只读取同一对象 ID，不保存第二套结论。内部编号稳定，默认对用户隐藏。

### 8.3 必须保持的不变量

1. 新材料创建新 Source，不得覆盖旧文件、旧哈希、人工文字或已审核版本。
2. ReviewDecision 和 OverrideDecision 不能改变 Claim 的核验状态。
3. 客户提供的信息可以带归属写入给经理的稿，必须保留口径缺口；客户来源不等于外部独立核实。公开网页和本机文件不得写成客户口头。
4. 宏观市场材料只支持宏观判断，不单独证明项目需求。
5. 模型记忆不得写成 Source。

## 9. 来源、核验与认识状态

来源类型、可访问状态、Claim 核验七态与 v0.4 第 9 节相同，仍写入对象。

**界面不再把七态做成主操作。** 普通界面不使用「已核实事实」作为主标签。

禁止行为与 v0.4 相同：不编造 URL、标题、作者、日期、引文、页码或数字；不把搜索摘要当原文；不把同源转载计为多个独立来源；不把模型记忆伪装成搜索结果；不把单个成功案例直接写成项目需求证明；没有原始数据时不生成精确 business case。

标红可收下，不解除上述禁止：模型仍不得发明数字；漏网时检查器标出，由人决定是否给经理看。

## 10. 首版界面与交互

### 10.1 P0 主界面

默认入口是**一块工作台**，三件事同时在：

1. **本轮问题（进度）**：顶上是本轮要决定的那句话；下列问题，每条可点成「还没写 / 草稿 / 这轮够用了」。点开一条才看到「为什么影响这轮决定」。
2. **给经理的稿（中间）**：就是将导出的 Word。点一节可写、可请模型写、可预览后收下。主名称用「给经理的稿」；短标签可用「本轮稿」。不用「内部稿」当产品壳。
3. **材料匣（旁边）**：文件和链接。没打开的网页不能当依据。点稿里标红的句子，匣子翻到对应材料。

废弃作为默认导航：内部稿审查侧栏、本题/材料/内部稿/导出四步跳转、过不过、核验七态、决策门状态栏、首页上的产品说明书式步骤条。

旧审查面可留成「技术详情」，默认不打开，不再加功能。

聊天是输入方式之一，不是界面。产品不是网站；本机看稿即可。

### 10.2 交互原则：简洁、分层、少键

本版失败过的原因不是颜色太浅，而是**把账本字段当成了操作面**。换面时下列规则进入验收，不是视觉偏好清单。

**层次靠点击，不靠一排键。**

- 第一层只看见：本轮决定、问题名 + 三档进度、稿的段落正文、材料名称。
- 点一下才展开：为什么影响决定、这一节候选预览、材料出处。
- 再点或进技术详情才出现：摘录原文、认识类型、核验、口径。
- 不要用始终可见的说明条教用户「这是什么产品」。布局自己说话。

**颜色分主次，不是整页加深。**

加深只用于当前正在处理的一节、标红（无来源）、过时（补料后）、以及人已点「这轮够用了」的问题。其余安静。不要用核验芯片当主色彩。

**默认可见的持久动作尽量少。**

允许长期放在台面上的，大约只有：

- 请模型写这一节（选中一节或一条问题后出现）；
- 预览时的收下 / 丢掉（或改完收下）；
- 导出 Word。

回题目列表走页眉产品名或题目名，不并排五个同等按钮。补材料在材料匣里追加，不单独做成顶栏键。新增一节在稿末用一处轻量入口，不要永远占顶栏。

**能去掉的下拉和修改键就去掉。**

默认不要出现：

- 核验七态下拉；
- 认识类型下拉（挂依据时不必先选类型）；
- 判断强度下拉；
- 问题状态下拉（改用点问题本身切换三档）；
- 过不过的一排确认键；
- 「去改稿 / 去依据 / 去过不过 / 去用这版」这类下一步键；
- 每个账本字段一个文本框（定位、口径、宏观、替代解释默认不出现）。

进度三档是点选问题，不是下拉。写稿时一个编辑区。补一份材料时，需要的字段才出现。

**预览后收下，不要两套找不到的正文。**

模型写出的是这一节的候选；人在稿上看前后差别后收下。沿用已有 revision。不要再做「先拟到侧栏，再找用这版」。

「看前后差别」是验收项，不是修辞：候选默认画在稿上时必须标明「还没收下」，并且能一键对出上一版正文。只把候选悄悄替换掉显示内容不算数。

**粘进来的长材料默认只给开头。**

人可以把整篇文字粘成一段原话，库里原样保存、一个字不改；但稿和材料匣默认只显示开头，点「看全文」才铺开。几千字的原话铺满两栏会把稿本身淹掉。

**发给模型的那一份按总预算截。** 超长原话会把提示词占满，把点开的那条问题和现稿挤出去；但只挂一条长材料时它应当整条送进去——稿要写细正靠它。因此按这一节所有已挂原话的总量设预算，超了才按条压，每条留下限。截断必须说明截了多少、后面的不得当作已知；不做摘要——摘要等于让模型改写原话。

**默认只铺开正在处理的那一节。** 其余各节第一层只给节名加一行现状（还没写 / 新挂了几条原话 / 几处标红 / 可能过时），点开才看全文；要通读整篇走「全部展开」。

**分组标题本身要看得出能点。** 收起／展开是常用动作，标题得是一条有边界、有计数的可点条，不能是一行灰小字。

## 16. MVP 完成标准

P-001样本 + 一个空白题能够完成：

1. 从一句任务创建题目，工作台顶上能看见本轮要决定什么；
2. 本轮问题用三档进度，人能点「这轮够用了」；
3. 材料进入匣子，未打开网页不能当依据，新材料不覆盖旧来源；
4. 选定一节后模型写出候选，人预览后收下或丢掉；
5. 空白无材料时写出缺口稿，不发明统计数字；
6. 无来源数字标红，可收下，红字随导出；点红字能到材料或看到未挂来源；

9. 导出 Word 读取同一篇给经理的稿；经理版之外还能导出详细版，摊开每节的原文摘录、来源与机械检查；
10. 默认台面没有审查侧栏、四步跳转、核验下拉和过不过主按钮；
11. 材料看得出对应哪一轮的哪条问题，本轮收口后旧材料仍带轮次显示；
12. 一节收下之后又挂了原话，那一节能说出来；候选能对出上一版。

## 17. 停止或转向条件

出现以下情况，应停止扩平台并重新收窄：

- 用户维护状态和引用的时间大于减少的返工；
- 用户只使用一次生成，随后立即回到聊天和 PPT；
- 稿填满了，但经理仍不清楚这轮要决定什么；

- 可编辑导出仍要求用户重新复制大部分内容；
- 真正有价值的只有文件问答或报告生成。

可能的转向：收缩为证据整理器；做成 Word/Notion 插件；只保留地产产业售前模板。

### 20.1 2026-08-19 走查后追加：轮次与稿的关系

第一轮在工作台上走完后，产品所有者提出「轮次没有分得很开」：第一轮的问题、第一轮的稿、第一轮的材料串不起来。核对代码属实，而且三件事不在同一层：

- **材料**已经挂在问题上（`sources.research_question_id`），只是界面收口后不认旧轮的标签。属界面缺陷，已修。
- **问题**已经有 `round_index`，归档正常。
- **给经理的稿完全没有轮次。** `deliverable_blocks` 没有 round 字段：第一轮的稿和第二轮的稿是同一批段落被反复重写。

**本版裁定：一篇稿，修订按轮次标记；不做「每轮一套稿」。**

理由是第 8.3 节不变量第 4 条——新视图只读取同一对象 ID，不保存第二套结论。每轮复制一套 DeliverableBlock 等于给同一批判断做多份副本，一旦某一轮改了口径，几份稿会各说各话。轮次要的是「这一版是第几轮收下的」，而 `deliverable_block_revisions` 本来就逐版留着，给修订记上轮次即可，不必复制段落。

落地方式（尚未实现，属下一刀）：schema 0.7 给 `deliverable_block_revisions` 加 `round_index`，收下时按项目当前轮写入；稿上每节显示「第 N 轮收下」；导出可选「导第 N 轮那一版」。段落对象仍只有一套。

### 20.2 2026-08-23 已裁定：给经理的稿到底是什么

**提出（2026-08-19）。** 产品所有者当时提出「不知道给经理的稿该怎么用」。现状是稿的五节标题直接由第一轮问题变来，因此稿的结构等于问题清单的结构。这意味着产出的更像「我这轮把每个问题答到什么程度」的记录，而第 5 节的 JTBD 要的是「经理能继续判断、修改和对客沟通」的材料。当时不裁定，留给现场题（P-004）导出的 Word 来回答，并在此之前冻结稿的分节方式和「经理视图」。

**裁定（2026-08-23，产品所有者）：给经理的稿就是工作台全部内容的汇总。**

本版 MVP 解决的是这一件事：经理吩咐一小句话 → 结合咨询框架把这句话拆成本轮问题 → 按问题搜资料、挂原话补充 → 把结果汇总成给经理的成果。给经理的稿是这条链子的出口，它的内容就是「经理这句话被拆成哪几条问题、每条问题搜到了什么、汇总起来说明了什么」。

因此：

1. **稿的结构继续跟着本轮问题清单走，不脱离。** 原先担心的「稿的结构等于问题清单的结构」不是缺陷，那正是这份稿该有的样子——经理拿到的就是他那句话被拆开、被填满之后的样子。
2. **稿是汇总，不是摘要。** 汇总意味着工作台上这一轮攒下的东西要在稿里出得来；第 6 节 M6 的详略规则不变：材料给了清单、年份、金额、比例、企业名就逐条写出来，不合并成「等」。压成三段白话等于没有汇总。
3. **冻结解除，但仍不新增「经理视图」。** 经理要看的东西已经是稿本身；再加一个视图等于给同一批判断存第二套结论，违反第 8.3 节不变量第 4 条。
4. **给客户的交付稿仍是另一件事，不在本版**（第 19 节）。

**这条裁定不授权的事**：不改追溯链、不改两份导出同源的规则、不开新业务类型。由这条引出的任何新想法仍按第 14 节扩展准入规则，先写进本 PRD 再动代码。

### 20.3 2026-08-20 第二轮怎么开（产品所有者裁定）

**台面是当前轮，上一轮收成文件夹。** 打开题目看到的是当前轮的问题、材料、稿；上一轮折成可展开的只读回看——那一轮的问题、每条挂了哪些材料、以及那一轮收下的是哪一版稿。回看不可改，改要回到当前轮。

**稿接着改，不重开。** 一篇稿、修订记轮次（第 20.1 节）。第二轮以补充为主，每节带上一轮的提示。每一轮的循环形状相同：搜 → 挂原话 → 按材料写 → 收下。

**第二轮起的问题来自审阅，不是重拆经理原话。** 模型读上一轮的稿、上一轮的问题和经理这一轮的反馈，找出哪条只答了一半、哪条只列了缺口、哪条被材料推翻，给出候选；人收下，也可以自己补一条。上一轮稿里的「下一步需补充……」是最直接的线索。

**经理反馈是一份材料，归属自成一档。** 反馈收进材料匣（`kind = manager_feedback`），原话存成受控副本，因此「看快照 / 从快照扒原话」照常可用。归属新增 `manager_feedback`：稿里引用必须写「据经理反馈」，**不得写成客户口径，也不得当成外部证据或已核实事实**。机械检查新增一项：经理反馈被推到「来源已检查 / 已交叉支持」或标成已独立核实时标出来。

至此第 8.3 节的归属分三档：客户提供、经理反馈、其余（公开网页与本机文件，不得写成任何人的口头）。

### 20.4 2026-08-22 台面层级与两份导出（本次落地）

**层级靠文件夹，不靠截断。** 本轮问题、材料、稿三栏都改成：能显示全就显示全，显示不全再省略，并且一律带悬停全文。收口过的轮次不再一条条铺在台面上——稿栏按轮加只读文件夹，材料栏把同一轮的分组收进一个「第 N 轮用过的材料」总文件夹，都默认收起。折叠状态只存在本机，不进账本。

**收口和「再加一条问题」分开。** 收口是换轮，不是补一条。它另起一块，上面先写清「收口后第 N 轮会变成只读文件夹」，按钮写明是从第 N 轮到第 N+1 轮。

**详细版回答的是「凭什么这么写」。** 经理版是整理稿，读的人要的是结论和出处；详细版是内部核对用的第二份，读的人要的是每句话背后那段原话。两份同源，所以详细版不会出现经理版里没有的结论。

### 20.5 2026-08-22 导出的排版（本次落地）

**导出不是把字倒进 .docx。** 两份导出都带真正的样式表：标题 1-4 用内置名并带大纲级别，
所以 Word 的导航窗格能用；正文 1.5 倍行距、首行缩进两字，条目悬挂缩进；「写入限制」「口径」
「来源」这类附注是灰色小字，不跟正文一样大。

**粘进来的材料按它本来的样子排，但一个字不改。** 制表符分列的连续行还原成真表格，
`表X-X / 图X` 当图表题，`一、/（一）/1、` 当条目，短且不带句读的行当材料内小标题。
判断不准就按普通段落处理——宁可少认，也不能替材料改写内容。

**材料和本文分得开。** 材料原文整块缩进、左边一条竖线、灰字；它自带的小标题不带大纲级别，
不进导航窗格。读的人一眼看得出哪些是我写的，哪些是原话。

- `recommended_question_labels`（拆本轮问题时喂给模型的提示，不是自动写入的问题，人仍要收下）。**共七条，见下面第「与原七层的对应」小节。**
- `labels`：沿用现有默认（`deliverable_block: 未命名的一节` 等），无需改动。

**与原七层的对应（2026-08-23 追加）。** docs/00 第 4 节当年对原七层（产业识别、政策层、产业分析层、产业图谱、产业链分析、本地基础层、延链机会层）做过审计，结论是「七层是好的分析维度，但被误当成必须按顺序走完的流程」，内容降级为按需调用的工作包（docs/09 第 4 节）。docs/14 把「商业地产章节包」归类为**后续验证假设**并注明「这是模板内容，不是核心对象，不得把地产词写入 `app/domain`」——本节就是那扇门后面的东西落地。最终七条：

| # | `recommended_question_labels` | 对应原七层 |
|---|---|---|
| 1 | 这轮研究的对象和边界到底是什么，经理那句话里指的是整个产业、某一段环节还是某个具体项目 | 产业识别（审计第 4.1 条把「先辨认概念与边界，避免研究对象漂移」列为最值得保留的一条） |

三条取舍要写清楚，否则以后会被人当成漏了：

1. **产业图谱不单列成一条，实质并进第 5 条。** 审计第 4.2 条第 2 点明确点名「产业图谱与产业链重叠：参与者、上下游、生态关系和价值分配边界不清」。单列一条等于把当年查出来的毛病搬回来。**同时区分清楚：「产业图谱」作为「要问什么」进模板（一句话提示）；作为「画出来的可编辑图」仍然不做**——后者是 docs/09 第 6 节 P0 要求第 7 条那个东西，需要新的数据模型和新界面，属于 docs/24 说的「第二个产品」，产品所有者已确认不塞进当前循环。
2. **第 6 条是缺口提示，不是搜索指令。** 产品所有者原话：「当地的信息最好还是自己搜集」。公开网页搜不到靠谱的本地一手信息，所以这一条要把人推向现场和客户，而不是推向再搜一次。它和第 7 条同一个性质，都是纪律条。
3. **延链机会层不进模板。** 审计第 4.2 条第 5 点批评它「从分析直接跳到延链机会，缺少决策标准、选项比较、风险和实施路径」；P-001 F-002 就是差点把东方甄选一个案例直接当成「P-001也能这么干」。方向该在证据够了之后由人决定，不该在拆问题阶段诱导模型去想。

**七条菜单 + 每轮最多五条，不冲突。** `round_questions.MAX_QUESTIONS = 5` 限的是每轮真正提出的问题数；模板给的是一份可借鉴的菜单（发给模型时的措辞是「参考标签，仅当原话明显同类才可借鉴」）。七选五恰好落回 docs/09 第 4 节那句「一个项目可以只运行其中三个工作包」。

  **（2026-08-23 修正：这条当时禁得太宽，见第 20.10 节。真正该禁的是「改变分析语义的字段」，界面文案字段不在禁列。）**

### 20.7 2026-08-23 已裁定并落地：新建题目时选模板，第二个题型是商业尽调（案头版）

第 20.6 节把默认模板固化下来之后，暴露出一个挡路的东西：**前端根本没有选模板的入口**（`frontend/report/app.js` 里一个 template 字样都没有），新建题目不传 `template_key`，后端一律用默认值。所以再加多少模板都点不到。这一节把「能选」和「第二个模板」一起落地——缺任何一个，另一个都是死的。

**裁定一：模板在新建题目时选，选定后这道题不再更换。**

理由：模板影响的是拆本轮问题时发给模型的参考提示（`round_questions._template_hints`）。做到一半换模板，已经收下的问题、已经写进稿的内容会跟新提示对不上，而经纬的轮次机制是「一篇稿、修订按轮次标记」（第 20.1 节），没有「这一轮换了个方法论」这种表达。要换就新建一道题。**因此不做「题目面板里改模板」，也不在 schema 上给换模板留位置。**

只有一个模板时不摆选择器——选不选都一样，多一栏只是噪音；两个及以上才出现。

**裁定二：第二个题型是商业尽调（案头版），`template_key = commercial_dd_desk`。**

选它不是因为它离产品所有者的经验近，恰恰相反——它离地产/产业规划最远，但**它对「每条结论都要挂得住证据」的要求最刚**（商业尽调报告经常要出具依赖函，出具方对第三方负法律责任），正好压在经纬唯一立得住的强项上（docs/24 第 2.2 节：开源界的人工把关全都在「计划」层，没有一个在「单条证据」层）。用它验证「同一条循环换个题型还成不成立」，是在压力最大的地方验。

**「案头版」三个字是边界，不是修饰。** 商业尽调的证据主体是 15–30 场客户访谈和 100–200 份问卷（docs/24 第 1.2 节），那一段经纬装不进。所以这个模板只覆盖公开材料能支撑的案头段，并且**要求它自己在提示里说出这条边界**，而不是假装能做全套。

七条问题提示（与产业链模板同构：五条实质问法 + 一条边界提示 + 一条出处纪律条）：

| # | `recommended_question_labels` | 出处 |
|---|---|---|
| 1 | 这笔交易的投资逻辑到底是什么，要验的几条命题分别是什么，哪几条是必须验、哪几条是有更好 | CDD 实务第 1 周就把投资逻辑拆成 3–5 条可检验命题，每条标 must-have / nice-to-have |
| 2 | 标的所在的市场有多大、增长靠什么撑，公开材料给的口径和年份对不对得上 | 市场评估工作流 |
| 3 | 直接竞对和替代方案各是谁，标的现在的相对位置靠什么撑住，这个说法有没有出处 | 竞争格局工作流（实务样本：6–12 家直接竞对 + 3–5 个替代品） |
| 4 | 客户是谁、集中在哪几家、公开材料能看出留存和流失到什么程度 | 客户与留存工作流 |
| 5 | 收入是怎么来的，定价、成本和单位经济性在公开材料里能看到多少、看不到哪些 | 单位经济性工作流 |
| 6 | 哪些结论只有访谈、问卷或数据室文件才拿得到，案头这一段的边界到哪里为止 | **边界提示**，与产业链模板第 6 条（区位「哪些必须自己跑现场」）同一个性质 |
| 7 | 每条结论现在挂的是哪份材料的原话，有没有哪条还只有说法、没有出处 | **出处纪律条**，对应依赖函的法律责任 |

**裁定三：`ProjectTemplate` 加一个 `listed` 布尔字段。**（当时写成「第 20.6 节的唯一例外」，2026-08-23 已按第 20.10 节改写成原则——`listed` 是界面字段，本来就不在禁列，不是例外。）

**这一步不做的：**

- **不做中途换模板**（理由见裁定一）。
- **不给模板加「描述」字段**：选择器的说明文字复用已有的 `name` 和 `brief_prompt`，不为了界面再开一个字段。

### 20.8 2026-08-23 已裁定并落地：界面的设计基线（Notion 式文档感）

界面反复返工是这个项目最长的一条尾巴——docs/20 第 6 节里 UI 缺陷占了大半，而且同一个补丁（「先点选再展开」）打了好几轮。根因不是某个按钮丑，是**从来没有一份写下来的设计基线**：每次改都在拍脑袋，改完又长出新的不一致。这一节把基线定死，以后改界面对着它改，不再一次次重新发明。

**风格方向由产品所有者指定：Notion 式的文档感**（参考 https://vibe-hub.org/style-notion）。要点是「文档像一张稿纸放在灰桌上，边界很浅」——内容优先，靠灰阶、细线和留白分层，而不是靠颜色块和粗边框。

**1. 色板（`:root` 的令牌，不许在规则里写死颜色）**

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#f7f7f5` | 画布（桌面），暖灰 |
| `--paper` | `#ffffff` | 稿纸：栏、卡片、顶栏 |
| `--ink` | `#37352f` | 正文，灰黑不是纯黑 |
| `--muted` | `#787774` | 附注、说明、标签 |
| `--faint` | `#9b9a97` | 再弱一档，只用于计数和占位 |
| `--line` | `#e9e9e7` | 细分割线，1px |
| `--line-strong` | `#dfdedb` | 输入框、按钮描边 |
| `--accent` | `#1a5c42` | 只用于「这一步的主动作」和已完成态 |
| `--accent-soft` | `#eef4f1` | 选中行的底色 |
| `--warn` / `--warn-bg` | `#b3261e` / `#fdf2f1` | 标红：无来源的数字和机构名 |
| `--stale` / `--stale-bg` | `#8a6100` / `#fbf6e9` | 可能过时、还缺什么 |

**2. 字号层级（`--fs-*`，只有这六档，不许现编）**

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--fs-title` | `1.5rem` | 题目名（首页 h1、顶栏 h1） |
| `--fs-section` | `0.8125rem` | 三栏的栏标题，加字距、用 `--muted`，是标签不是标题 |
| `--fs-body` | `1rem` | 正文、按钮、输入框——**按钮和正文同字号，这是按钮大小统一的前提** |
| `--fs-note` | `0.875rem` | 附注、说明、原话、`.why` `.note` `.hint` |
| `--fs-meta` | `0.8125rem` | 计数、状态标签、分组标题 |
| `--lh-body` | `1.7` | 稿的正文行距；其余默认 `1.55` |

**3. 按钮只有四档，且四档同高同字号**

`primary`（实心，一屏最多一个）／`secondary`（描边，与 primary 并排时同尺寸）／`ghost`（弱描边，卡片内动作）／`quiet`（纯文字，破坏性或次要动作）。四档共用同一套 `padding`、`font-size: var(--fs-body)`、`border-radius: 4px`。**并排的两个按钮必须同档或同尺寸**——「导出整理稿」和「导出详细版」一大一小就是这条没定下来的结果。

**4. 三条形状规则**

- **圆角一律 4px**，只有进度胶囊用 999px。Notion 不用大圆角。
- **不用阴影分层**，用 1px 细线和留白。
- **状态不能只靠「消失」表达**：一个动作不可用时，要么给出灰掉的按钮加一句原因，要么给一句说明。这条是 PDF 那次的教训（第 8.27 节），现在升成通则。

**5. 首页和工作台是两屏，不是一页**

打开题目前只看到题目列表，打开后只看到工作台。`[hidden]` 必须真的隐藏——**这条之前是坏的**：`#bench` 用 ID 选择器写了 `display: flex`，压过了浏览器给 `[hidden]` 的 `display: none`，所以工作台一直挂在首页下面。修法是全局 `[hidden] { display: none !important; }`，不是给每个元素单独加类。

**这一节不做的**：不换技术栈、不引 CSS 框架、不做暗色模式、不改三栏结构、不动任何账本语义。基线只管长相和层级。

### 20.9 2026-08-23 已裁定并落地：导出可以存到题目文件夹，但不许和受控副本混在一起

产品所有者提出「材料的链接和文件都存在同一个文件夹，导出也导出到同一个项目文件夹」。**前半句其实已经成立**：受控副本本来就按题目分文件夹（`var/<db>-files/P-005/sources/S-022/snapshot.bin`），网页快照和上传文件都落在那里。缺的只有导出——它走浏览器下载，落在系统的下载目录。

**裁定：导出多一个「存到题目文件夹」，落到人话路径；受控副本继续待在 `var/`，两者分开放。**

不把导出丢进受控副本那个文件夹，理由是第三条，前两条只是不好用：

1. 那里的文件名是对象 ID（`S-022/snapshot.bin`），人打开根本不知道是什么；
2. 路径深在代码目录里、且被 `.gitignore` 忽略，不是放交付物的地方；
3. **受控副本是账本的一部分，不能跟人会去整理的文件混在一起。** 人删掉一个快照，那条原话就失去了受控副本，追溯链断在那儿，而且系统不会提示。这跟第 8.27 节做 `remove_source` 时「挂了东西的一律不给删」是同一条道理：**能删的和不能删的必须分开放。**

**落地形状：**

- 路径：`<项目根>/导出/<题目名>/<日期> <整理稿|详细版>.<扩展名>`。题目名做文件名安全处理（去掉 `\ / : * ? " < > |` 和控制字符，压掉首尾空白和点，超长截断），空名退回题目 ID。
- 同名不覆盖：已存在就加 ` (2)`、` (3)`。**导出永远不覆盖已经存在的文件**，理由同上——人可能已经把上一版发出去了。
- 浏览器下载保留，不是替换。接口多一个可选参数决定要不要顺便存一份。
- 不写进账本：存到哪儿只是一次文件操作，不产生对象、不改核验状态、不进追溯链。

**这一节不做的**：不让人配置导出目录（多一个配置就多一处能指到系统任意位置的地方，也多一堆要处理的失败情形）；不做「打开这个文件夹」的按钮（本机 HTTP 服务不该去调系统的文件管理器）；**不动受控副本的存放方式**。

### 20.10 2026-08-23 已裁定并落地：模板字段的规则改写，以及模板介绍页

**一、把「不新增模板字段」改写成原则。**

第 20.6 节写的是「不新增模板字段」，第 20.7 节加 `listed` 时又写「这是唯一例外」。这条规则一开始就禁错了范围：再加一个字段，「唯一例外」就成了废话，而攒例外是规则失效的开始。

**真正该禁的是「改变分析语义的字段」，不是「所有字段」。** 改写成两条：

- **不许加会改变模型怎么理解材料的字段**：固定章节清单、证据归属规则、核验状态映射、材料可信度权重这类。它们一旦进模板，同一批材料在不同模板下会得出不同结论，等于给追溯链开了后门。要加必须先单独裁定。
- **可以加纯界面文案字段**：`listed`、`intro`、`steps`、`example` 这类。它们只影响人看到什么，动不了任何分析结果。加之前问一句：**「换掉这个字段的值，模型的输出会不会变？」会变就属于上一条，不会变就可以加。**

按新规则，`listed` 本来就不是例外，第 20.7 节那句措辞一并更正。

**二、模板介绍页（产品所有者指定做成独立页）。**

现在选模板时只看得到一个名字和一句提示，**选之前不知道选了它会发生什么**。第 8.26 节讨论过一次「像术语图鉴那样的页面」，当时按第 19 节「不做知识库」挡掉了——**那次挡对了一半**：挡掉的是「跟工作台无关、没事点开逛的咨询百科」，而产品所有者这次要的是**产品自己的说明书**，只描述已经装进来的模板，不引入任何外部知识。这两件事不是一回事，后者该做。

落地：

- 模板配置加三个界面字段：`intro`（这个模板是干什么活的）、`steps`（大致几步）、`example`（一个模拟样例，说明这类活长什么样）。**内容必须对得上该模板真实的 `recommended_question_labels`，不许写套话。**
- 新增只读接口和页面：列出所有 `listed` 的模板，每个显示介绍、七条问法、步骤、样例。从首页进得去。
- 样例是**静态配置文案**，不是材料、不进材料匣、不进追溯链、不会被当成证据。这一条要写进页面本身，免得人误以为样例里的数字能用。

**这一节不做的**：不做外部咨询知识的百科（第 19 节仍然有效）；不让人在界面上编辑模板介绍（模板是仓库里的配置文件，由写代码的人改）；**不按尽调的子类型拆成多个模板**——现有模板的第 6 条边界提示已经在说清楚覆盖到哪，等真接了一单撑不住的活再拆才有依据。

### 20.11 2026-08-23 已裁定并落地：把「写」的四个漏洞堵上（重复、数字、落点、改一节牵动谁）

产品所有者点了四件事一起做。它们不是四个功能，是同一个判断的四个面：**模型能写出通顺的东西，不代表写出来的东西站得住；工作台的活是让人一眼看出哪里站不住。**

**（1）稿的重复性——改提示词，最便宜。**
先量了真实的 P-005 已收正文：13 条正文里 **9 条（61%）在说材料没说什么**，5 条以「因此无法……」收尾，缺口词出现 10 次，小结里有 **7 段六字片段是从正文原样抄下来的**。所以改的是两处：
- `_REVISION_PROMPT` 加一段：事实和缺口分开写，缺口按小节合并成一条收尾，小结不许重复正文里的数字。
- `checks.py` 加 `repeated_phrases()`，两种：`gap_spread`（条目 ≥4 且缺口行数×2 > 条目数）、`summary_echo`（小结与正文重合的六字片段合并成句后 ≥2 处）。
**只提示，不拦截**——跟这里所有机械检查一样（第 8.3 节）。

**（2）数字清单——稿里每个数字单独一行，挂出处。**
模型编数字比编论述隐蔽：一段论述读着不对人能看出来，一个「19.1 亿元」混在通顺句子里人不会怀疑。`app/projections/numbers.py` 把正文里的数字逐个列出来，标明在哪条已挂原话里找得到；找不到的整行标红。占位稿不算。
**这张表对的是「这个数字在已挂原话里出不出现」，不是「这个数字对不对」**——挂上了也可能是材料本身写错。这句话印在表底下。

**（3）拆问题时定「这条问题落在稿的哪一节」——先立骨架再找料。**
schema 升到 0.8，`research_questions` 加 `target_block_id`。拆问题的提示词多要一个 `section` 字段：从现有小节名里挑，或提一个 6–14 字的新名，**看不出该落哪一节就留空**。收下时按小节名匹配（忽略空格和常见标点），**对不上就留空，绝不猜**——跟材料 `research_question_id` 那条规矩同一个理由：猜错了人不会发现，而这条链子本来就是为了让人知道材料该往哪儿放。
人可以随时自己改：`POST /research-questions/{id}/target-block`，传空就是改回「还没定」。左栏每条问题都写着落点，没定的也写「还没定落在哪一节」——**状态不能只靠「消失」表达**（第 20.8 节）。

**（4）改一节，别的哪几节跟着要看——最难也最根本。**
三类咨询活真正累人的地方都是「改」不是「写」。`cross_section_impact()` 只沿**已经挂着的关系**算四种：
1. `changed_number`——这一版待收的改稿把某个数字改掉了，**别的小节还照旧写着老数**。最要紧的一种，不用展开就亮出来，标红。
2. `same_claim`——同一条主张挂在两节上。
3. `same_source`——同一份材料。
4. `same_number`——两节写着同一个数。

**真机上第一版是错的，值得记下来**：一开始所有数字都算，结果 P-004 的每一节都跟其余每一节「相关」，理由全是「同一个数字：70%」。**一个哪儿都亮的提示等于没提示。** 改判定：带亿／万的量级要 ≥2 位有效数字，其余要 ≥3 位；`70%`、`3`、年份都不算。改完之后 P-004 和 P-005 一条都不亮——这是诚实的结果，那两个题目的每一节确实各用各的材料。

**这一节明确不做的**：不自动改别的小节（列出来不等于那几节就错了，改不改是人的事）；不做语义相似度判断（算不出来就不写，不猜）；不拦截收下和导出。


### 20.12 2026-08-23 已裁定并落地：模板加到五个，并且每份模板都要自己交代来历

**产品所有者纠正了一个我自己写错的判断。** 我在第 20.10 节之后写过「加更多模板已经不是最值钱的方向，第三第四个只是重复验证同一件事」。这句话**偷换了概念**：第三个模板确实不再给「骨架能不能换题型」提供新的*验证*价值，但那说的是验证价值，不是*产品*价值。docs/24 第 1.4 节自己排过扩张顺序，还写着「这四个都不需要改变产品的基本形状」。前一个判断作废。

**而且产品所有者说明了一件改变前提的事**：这个工具不是只给他一个人用，目标是给尽量多的人用，同时也是他理解不同咨询工种的方式。**这让「加模板」更值得做，也让「模板可以随便写」更危险**——使用者分不出哪条问法有来处、哪条是拟的。

**所以这一节裁定的是两件事，缺一不可：**

**（1）模板从两个加到五个。** 按 docs/24 第 1.4 节排好的契合度顺序：

| key | 名字 | 走查状态 |
|---|---|---|
| `industry_chain_analysis_presales` | 产业链分析（低信息售前研究） | 已走查（P-004） |
| `commercial_dd_desk` | 商业尽调（案头版） | 已走查（P-005） |
| `industry_plan_context` | 产业规划（背景与对标段） | 只搭了骨架 |
| `strategy_fact_base` | 战略咨询（事实基础段） | 只搭了骨架 |
| `competitive_intel_sweep` | 竞争情报（定期深挖） | 只搭了骨架 |

加一个模板是**写一个 JSON 文件、零行代码**：`load_templates()` 扫 `app/templates/*/template.json` 自动发现，选模板栏、介绍页、测试全部自动接上。这是第 20.6 节那条接缝真的在工作的证据。

**（2）模板必须自己交代来历。** 新增三个纯界面字段（按第 20.10 节的判断标准：换掉它们的值模型输出不变，所以允许加）：

- `walked`：有没有拿真题从头走到尾走过。**没走查过的不许在页面上装成走查过的。** 介绍页标题旁一个琥珀色的牌子，选模板的选项文字里带「（还没走查过）」，选中时当场给一段提示。
- `status_note`：这个状态的一句话说明。
- `provenance`：**七条问法逐条说清从哪来。** 条数必须等于 `recommended_question_labels` 的条数，有测试钉住。

**「模板的问法要挂来源」这条，是把这个工具自己的规矩用在自己身上。** 这里要求每条主张挂已挂原话的出处；那生成这些主张的问法，没道理可以来路不明。

**（3）介绍页加「这些活现在装不进来」一节**，把 docs/24 第 1.4 节那四类（技术尽调、组织与人力咨询、市场研究的定量部分、竞争情报的常年卡片维护）和理由写出来。**说清做不了什么，比让人自己撞上去省事**；对一个要给别人看的产品来说，边界写得出来比功能多更有说服力。

**排序也跟着改**：默认的排头，走查过的排在没走查过的前面——人不细看也先碰到验过的那几个。

**这一节明确不做的**：不为装不进来的四类活写模板（写了会在介绍页上显得跟别的一样权威，而它撑不住）；不让人在界面上编辑模板（模板是仓库里的配置文件）；不因为多了三个模板就去改分析语义——五份模板共用同一条循环、同一套检查、同一条追溯链。


### 20.13 2026-08-23 已裁定并落地：竞品分析拆成两个模板，七份模板全部试过问法，走查状态改成三档

产品所有者点名要竞品分析，并说「这个很重要，而且可以细分」，加完之后「都走查一遍」。

**（1）竞品分析拆成两个，跟已有的竞争情报凑成三条互不重叠的轴。**

调研里最有用的一条实证：**行业里把「竞品分析」和「竞品基准评测」分得很清——前者描述对手主张了什么，后者比较对手表现如何。** 这条界线几乎就是本产品边界的现成表述：**这条循环擅长「主张类证据」，不擅长「表现类证据」；前者是能逐字抠出来的文本，后者是必须算出来的数字。**

| 轴 | 模板 | 比什么 |
|---|---|---|
| 时间轴 | `competitive_intel_sweep` 竞争情报（定期深挖） | 这一段时间发生了什么 |
| 定位轴 | `competitor_positioning_desk` 竞品分析（定位与主张对标） | 各家自己怎么说、面向谁、定价口径怎么设 |
| 功能轴 | `competitor_feature_desk` 竞品分析（产品与功能对标） | 功能逐项对照 |

功能对标那一份**必须在介绍里写清代价**：行业通行产出是功能矩阵 + 加权打分 + 雷达图，而这条循环不做表、不做算、不出图，只能做按功能主题分节的文字对照。**要一张勾选表的话，这个模板给不了。**

调研同时确认了**装不进来的清单又长了**：竞品基准评测（必须算）、Win/Loss（唯一证据是当事人访谈）、战棋推演（必须真人多轮）、电商货架监测（必须常年高频 + SKU 级 + 数值）、战略群组图（产出必须是二维图）、Battlecard 卡片库（价值在常年维护和分发）、专利版图（价值在分布统计）。**都不写模板**——写了会在介绍页上显得跟别的一样权威，而它撑不住。

**（2）走查状态从两档改成三档。**

原来只有「已走查 / 只搭了骨架」。这一轮实际能做的是**拿真题逐条试问法**（搜得到吗、重复吗、空吗），而**整条循环（写稿、收下、导出）没走**。把这两件事混成一个「已走查」就是在骗人。所以 `walked: bool` 改成 `verification` 三档：

- `loop_walked` **已在真题上走查过**——整条循环从头走到尾。
- `questions_probed` **问法在真题上试过，整条循环还没走**——七条逐条搜过，写稿那几步还没验。
- `skeleton` **只搭了骨架，还没试过**。

认不出的值一律退回最低档：**宁可说自己没验过，不要说验过了。**

**（3）五份模板试过问法，改了 11 条。** 试问法不是走过场，真的推翻了东西：

- **删掉一条**：定位模板里的招聘那条，在国内基本搜不到（招聘站挡爬虫、搜产品名还撞上同名的招聘产品），而且跟公开表态那条问的是同一件事。换成归拢条——原来七条里一条综合型都没有。
- **合并四组重复**：产业规划的对标与归因（吃同一批材料）、战略咨询的首尾（都是工作流定位）、竞争情报的出处性质与出处数量（同一次核对动作）、功能对标的卖点与文档（扒回来是同一份原话）。
- **补进四条**：本地已发文件与领导表态、准入与合规门槛、财报与电话会、监管与诉讼记录——都是实搜产出很高、而原来七条里一条都没覆盖的。
- **一个跨模板的共性毛病**：**纪律半句常被塞进搜索条的尾巴**（「够不够」「准不准」）。那些半句本身都对，但挂在搜索条上会让执行的人搜到一半停下来自我怀疑。**新规矩：搜索条只写去搜什么，所有「够不够、准不准」一律归到最后的纪律条。**

问法的健康配比也是这次量出来的：**搜索型 4–5 条撑主体，确认型 1 条开头，综合与纪律 1–2 条收尾。**

**（4）试问法撞出了一个比模板更要紧的东西——这条循环自己的盲点。**

这个工具的硬门槛是「原话必须逐字来自快照」。**但那道门槛挡不住来源本身是假的。** 实搜里反复撞到三类：

1. **扒得出，但不是法定口径**——中文长尾里服务商和渠道商的 SEO 页常排在官方前面，页上真有价格和参数、也真能逐字扒。挂上去就是把渠道话术当官方定价。镜像站冒充的更新日志同理。
2. **搜得到，但扒不出来**——问答社区、种草社区、招聘站在搜索结果里出现频率极高，却挡爬虫，快照存不下正文。只能当线索，不能当来源。
3. **官网抓不到，不等于这家没有公开信息**——前端渲染的官网抓下来只有网页标签。要退到应用商店介绍页或帮助中心，而不是记成「查无此项」，否则会把技术问题误报成事实结论。

**结论一句话：扒得出原话，不等于这个来源算数。** 这三条写进介绍页（跟具体模板无关，是循环本身的盲点）。**这是本轮最值钱的发现，而且只有真的去搜才撞得到。**

**这一节不做的**：不给上面那七类装不进来的竞品活写模板；不因为多了模板就去改分析语义——七份模板共用同一条循环、同一套检查、同一条追溯链。


### 20.14 2026-08-26 上线第一版之后的回修：README、内部指路、借来的权威

产品所有者昨天让 codex 检查代码、封装成 Windows 应用并把第一版推上了 GitHub。这一节记回修的三件事。

**（1）README 重写。** 产品所有者的原话是「用户不明白有什么功能，流程如何，我们有几种模板」。原 README 的硬伤有三条：

- **模板名全是错的**——写成「品牌定位对标」「产品功能对标」「产业规划背景研究」「战略事实基础」，而实际模板名是「竞品分析（定位与主张对标）」等。**用户照 README 去界面里找，会找不到那个模板，只会以为是自己看错了。**
- **最能打的功能一个都没写**——机械检查那一整套（没挂来源的数字、数字清单、客户口头被写成已核实、经理反馈被当外部证据、宏观数据证项目需求、重复、跨节影响）在 README 里一个字都没有。那才是这个工具跟「让 AI 写份报告」的区别。
- **没有流程图**，「流程如何」只能靠一段五步列表想象。

重写后的 README：先用一句真实场景开头（半个月后经理问「这个数是哪来的」），用一张对照表说清跟「让 AI 写报告」的四点区别，用一张 Mermaid 流程图画出整条循环**并把三道人工闸门标成绿框**，列出七个模板的真实名字和各自的走查状态，最后写清做不到什么。

**新增 `tests/test_readme.py` 钉住**：每个模板名必须逐字出现在 README 里；模板个数必须对得上；三档状态的说法必须跟 `VERIFICATION_LEVELS` 一致；README 里不许出现 `PRD` / `docs/` 这类内部文档字样。

**（2）内部指路改回来。** codex 为了让公开仓库不指向未公开的文档，把代码注释和测试里的 `PRD 20.x`、`docs/20 §6`、「流水账第 N 条」抹掉了 **40 处**。产品所有者要求改回来，已全部恢复（连带自动脚本没覆盖的整段改写也手工修回）。

**理由值得写下来**：这个产品要求「每条结论挂得住出处」，**代码里的每条规矩也一样——规矩为什么长这样，必须指得回它是哪次裁定的结果**。抹掉指路，等于把这个工具自己最看重的属性从自己身上拿掉了。同时在 `DEVELOPMENT.md` 里加了一段，向外部读者说明这些指路指向未公开的内部决策记录，注释本身已经把理由写在原地，指路只是维护者的书签。

**（3）新增检查：借来的权威。** 用真材料给五个模板做端到端走查时，往每份稿里塞了一条编造的机构归属（「麦肯锡的调研显示」「Gartner 据此认为」「IDC 预计」「中信证券预计」「欧睿国际预计」）。结果：**编造的数字五份全被标红，编造的机构一个都没抓到**——`_ORG` 正则只认「…有限公司／集团／研究院」这几个中文后缀。

**这是比编造数字更危险的一类**：数字还会被数字清单标红，而一句「IDC 预计」读上去就像已经有出处了。现在加了两条识别——机构后缀扩到研究所／证券／咨询／事务所／银行／基金／资本／协会／学会／大学／智库，以及**归属句式**（名字 + 预计／认为／指出／显示／表示／预测／估计）。

**同时定了一条使用这条检查的原则**：**宁可漏报也不要吵**——一个老误报的提示，人两天就学会无视它，那比没有还糟。所以名字要修干净（「麦肯锡的调研」→「麦肯锡」）、带句子字（是／不／而／但／也／就／只）的一律不报、常见叙述词进停用表。验收标准是双向的：**五份中毒稿必须全抓到，五份干净稿必须一个都不报。**

**（4）走查状态从三档改了中间那一档的定义。** 原来的中间档是「问法在真题上试过，整条循环还没走」。这一轮五个模板都用**真实公开材料**走通了整条循环（挂材料、逐字扒原话、写稿、收下、核验、导出，数字全部挂得住出处），但**「模型按这个模板拟问题和写稿」那两步是人代做的**——沙盒里没有模型密钥，本机服务也连不上。

所以中间档改名为 `walked_by_hand`，说法是「真材料走通了，模型那一步还没验」。**差一步就是差一步，不许含糊。** 要升到 `loop_walked`，得在产品所有者自己机器上接好模型、拿每个模板各跑一道真题。

**这一节不做的**：不代替产品所有者推 GitHub——上线是他的动作，也是他的判断。


### 20.15 2026-08-26 已裁定并落地：拆错的问题要能真去掉

产品所有者用新版走第一道真题（「目前 AIGC 有什么突出的新兴公司」）时踩到的。

**现象**：这一轮本来要决定的是「先找出公司 → 列基础信息 → 再看成果和产品方向」，但模型拆出来的第一条直接从「找公司信息」开头，跳过了「先怎么圈定这个名单」。第一条歪了，后面按它搜回来的材料全跟着歪。

**真正的缺口不是模型拆歪——那难免——而是拆歪之后没有清理手段。** 材料早就能真去掉（没挂原话的），而**问题只有「这轮先不用」，没有删除**。于是错问题永远躺在抽屉里，底下的材料也跟着赖着，越攒越多。

**裁定：照搬 `remove_source` 立下的规矩。** 新增 `remove_research_question`：

- **没归着任何材料和网页候选的问题，可以真去掉。**
- **归着的拒绝，并说清挂着几份**，同时把两条出路都说出来：先把材料改归到别的问题、或者把材料本身去掉；不想清理就点「这轮先不用」收起来。
- 上一轮已收口的问题不许动（沿用既有的轮次只读规矩）。
- 删问题**不带走材料**——材料只是失去归属，退回「还没标对应问题」那个本来就合法的状态。

**为什么归着材料就不许删**：材料的「归到哪条问题」是人手工点的。删掉问题会让那批材料悄悄退回未归属，**人不会收到任何提示**，下一轮又会重新捡起来——那正是这次踩到的坑的放大版。

界面上「去掉这条」跟材料一样走两步确认，并且**「这轮先不用的」抽屉里也要有**——那儿正是拆歪之后堆着的地方。

**这一节没有解决的、更深的一条（记下来，等裁定）**：产品所有者那道题的形状是**「名单本身还不知道，要先把名单找出来」**（参与者盘点／赛道扫描）。现有七个模板里，竞品分析（定位与主张对标）的第一条问法是「要跟谁比——名单先定死」，**它假设名单已知**。拿它去做「有哪些公司」，第一条就错位了。这不是提示词问题，是**模板覆盖面的缺口**。要不要补一个「参与者盘点」模板，由产品所有者定。


### 20.16 2026-08-26 已裁定并落地：第八个模板「参与者盘点」，以及选模板要靠例题不靠定义

**（1）新增 `landscape_scan` 参与者盘点（赛道扫描）。** 第 20.15 节末尾那条开着的问题，产品所有者裁定要做。

补的是一个**真实撞到的缺口**：做「某某赛道有哪些新兴公司」这类活时，**名单本身就是要找的东西**；而竞品分析（定位与主张对标）的第一条问法是「要跟谁比——名单先定死」，**它假设名单已知**。用它做盘点，第一步就错位——模型答不了「名单先定死」，只好跳过去直接搜公司信息，后面材料全跟着歪。

两个模板的边界写成一句话，印在介绍页上：**竞品分析假设你已经知道跟谁比，参与者盘点是名单还不知道、要先找出来。** 先盘点圈名单，再换竞品分析逐家深挖。

七条问法的骨架是：**先定边界和形容词**（什么算「在这个赛道里」、什么算「突出」「新兴」）→ **多个口子分头捞名字**（融资库、榜单、大厂投资名单、应用商店榜、协会名录、展会）→ 记出处和时间点 → 补官方基本信息 → 各家自己宣称在做什么 → **分类** → 出处纪律。最要紧的是最后一条：**「突出」是榜单排的还是事实撑的，必须分开说**——盘点最容易把别人的排序当成自己的判断。

状态是 `skeleton`（只搭了骨架，还没试过）。产品所有者手上那道 AIGC 题就是它天然的第一次走查。

**（2）选模板要靠例题，不靠定义。** 产品所有者的原话是「**我现在我是开发者都搞不懂了**」——连写这套东西的人都要想一下选哪个，别人就直接放弃了。

原因是介绍页只给抽象定义（「各家自己怎么说、面向谁」），而人手上拿着的是一句具体的经理原话。**两者对不上。**

所以加两样：

- 每个模板配 **`sample_briefs`：三句典型的经理原话**，摆在介绍正文之前。
- 介绍页最上面（**在页签之上，因为选模板发生在读介绍之前**）加一张「**不确定选哪个？看哪句话最像你手上这道题**」对照表：每个模板一句原话，点右边的名字直接跳过去。

这两个都是纯界面字段，按第 20.10 节的判断标准（换掉值模型输出不变）可以加。

**（3）顺手拆掉一个写死的数字。** 封装冒烟测试里写着 `len(templates) == 7`，加第八个模板时它红了——**而它红得没道理**：装包真正的风险是模板 JSON 没被打进去（数量会变 0），不是数量等不等于某个字面量。改成跟注册表比，并要求大于 0。`test_desktop`、`test_template_walk` 同样处理。**以后加模板不该让封装测试红。**


### 20.17 2026-08-26 已裁定并落地：桌面版不再用弹窗吊着命，版本号必须随时看得见

产品所有者用新版时提的两条，查下来**是同一类问题的两面：人无法判断自己面对的是什么**。

**（1）「每次打开都有个弹窗，按取消才消失」——那个弹窗就是程序的生命线。**

原来的 `_run_controller()` 是一个 `while True` 的 Windows MessageBox 循环：「是」重开页面、「否」打开数据目录、「取消」`break` 掉循环 → 服务器停掉 → 经纬退出。**于是让弹窗消失的唯一办法，正好是那个关掉程序的选项。** 产品所有者按了取消，程序就悄悄关了，而浏览器里那一页还在，看上去像还开着。

**裁定：退出、打开数据目录、报平安全部交给页面，桌面进程只安静地等着。**

- `POST /app/heartbeat`：页面每 30 秒报一次平安。桌面进程 180 秒收不到就自己退出——**关掉浏览器页面，经纬跟着退出，不留没有界面的孤儿进程**。窗口留到 180 秒，是因为浏览器会把后台标签的定时器压到 60 秒一拍，得够漏两三拍。
- `POST /app/quit`、`POST /app/data-folder`：页面右上角两个按钮，退出走两步确认。
- **弹窗只留给报错**（端口被占用、启动失败）。有测试钉住 `_MB_YESNOCANCEL` 不许再出现在 `desktop.py` 里。

这几个接口只在桌面版登记了控制器时存在；`app.cli serve` 不登记，它们返回 404，命令行行为一个字不变。

**（2）「打开后好像版本还是以前的」——旧进程占着端口，新进程只是打开浏览器。**

单实例互斥锁发现「已经在运行」时，原来只做一件事：打开浏览器指向 8765 然后退出。**如果占着那个端口的是旧版本，人看到的就是旧版页面，而且没有任何地方能看出来。** 产品所有者从源码启动新版时，旧的 exe 还在跑，撞的就是这个。

两条一起修：

- 启动时先问一句 `GET /app/info`：**已经在跑的那个是哪一版？** 跟本次要启动的版本不一致就明确报错，告诉他去已打开的页面上点「退出经纬」再重来，而不是默默打开旧页面。
- **页面左上角常显版本号。** 这是「我现在跑的到底是哪一版」这个问题的根本答案——产品所有者前一天就问过一次，当时我的回答是「去看模板状态牌的措辞」，那是绕路。**该显示的东西就直接显示。**

**（3）顺带一条更一般的教训**：`app.cli serve` 启动横幅是手写的路由清单，加了四个接口之后它就漏了——是 codex 加的 `test_route_banner` 当场逮住的。**手写的清单一定会漂移，除非有测试盯着它。**
