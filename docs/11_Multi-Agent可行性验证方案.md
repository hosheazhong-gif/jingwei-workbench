# Multi-Agent 可行性验证方案

> 日期：2026-08-12  
> 状态：P1 以后候选实验；不属于 PRD v0.4 的 P0 验证，也不因 P0 完成而自动启动

## 1. 当前判断

Multi-Agent 在技术上可实现，但“能够运行”不等于“对经纬更有效”。经纬首版保持统一项目编排、证据台账、人工审批和版本控制，同时在架构上允许部分研究任务以后由受限 Agent 执行。

P0 固定使用 Workflow，只在架构上保留 ExecutionStrategy 接缝。该实验不与P-001最小闭环同时启动，也不在 P0 完成后自动启动。只有进入 P1、固定 Workflow 已跑通、Source—Claim—DeliverableBlock 追溯和人工补料机制稳定，而且真实研究任务仍因动态换词、多轮补证或并行核验产生明显人工瓶颈时，才进入 A/B/C 对照。

当前较适合 Agent 化的任务：政策原文追溯、案例多轮搜索、区位与竞品公开研究。Excel 清洗、公式检查、引用格式、版本记录等优先采用确定性程序或固定 Workflow。策略综合与最终可行性判断由人主导。

## 2. 首个验证任务

> 搜索P-001 冷链园区周边及可比区域的冷链园区项目，整理租金、空间类型、时间、地点、来源和可比性，形成供内部讨论的竞品表。

选择该任务是因为它目标明确、公开数据不完整、需要多轮搜索和来源核验，同时结果可由人工逐项检查。

## 3. 三种对照方式

### A｜固定 Workflow

```text
固定关键词与来源范围
→ 抽取预设字段
→ 去重与单位转换
→ 输出竞品表
→ 人工审核
```

### B｜单一研究 Agent

```text
接收目标与停止条件
→ 自主制定搜索顺序
→ 根据结果换词、补证和追溯原始来源
→ 统一输出证据卡与竞品表
→ 人工审核
```

### C｜受编排 Multi-Agent

```text
协调器
├─ 市场研究 Agent：寻找可比项目与租金线索
├─ 数据处理 Agent：统一字段、单位、时间和空间类型
└─ 核验 Agent：追溯来源、检查可比性和反证
→ 协调器处理冲突并生成候选竞品表
→ 人工审核
```

三组使用相同问题、可用材料、时间边界和公开来源权限。不得通过扩大搜索范围或人工暗中补充答案使某组获得额外优势。

## 4. 共同输出字段

- 项目名称与位置；
- 空间/物业类型；
- 租金及单位；
- 数据时间；
- 出租、挂牌或报道口径；
- 原始来源与精确位置；
- 与P-001的相似点和关键差异；
- 可比性状态：可比、部分可比、不可比、待核验；
- 缺失信息和下一最小补证动作。

## 5. 评价维度

### 5.1 质量

- 有效且可比的项目覆盖情况；
- 原始来源和精确引用覆盖情况；
- 数字、单位、时间和物业类型错误；
- 将挂牌价、成交价、报价或不同物业误作同口径的情况；
- 能否主动暴露反证、不可比项和信息缺口。

### 5.2 人工成本

- 人工修改、排除和补证次数；
- 从结果产生到可供内部讨论所需的人工复核时间；
- 是否容易理解某条结论由哪个步骤产生。

### 5.3 系统成本与稳定性

- 总运行时间；
- 搜索、模型与工具调用量；
- 重复搜索和重复证据；
- 失败后能否从任务状态继续；
- 重复运行时关键结论是否出现不可解释的漂移。

首轮不预设脱离基线的武断百分比门槛。先记录 A/B/C 的真实结果，再判断 Multi-Agent 带来的质量或人工复核改善是否足以抵消延迟、费用和协调复杂度。

## 6. 采用规则

- 如果固定 Workflow 已能稳定完成，则不为展示效果升级为 Agent；
- 如果单 Agent 能处理动态搜索和补证，则不额外拆成多个 Agent；
- 只有当任务能明显并行、角色需要不同工具或上下文、输出可独立核验，且协调成本可控时，才采用 Multi-Agent；
- 无论采用哪种执行方式，证据、发现、冲突和人工决定都必须回到统一项目状态；
- Agent 不得自行发布客户材料、扩大数据权限或将未核验结果升级为最终建议。

## 6.1 启动门槛

同时满足以下条件才执行本实验：

1. P-001 P0 已完成一次端到端人工测试；
2. 固定 Workflow 的质量、耗时和人工修改量已有基线；
3. 失败主要来自动态研究决策，而不是文件解析、字段设计或界面问题；
4. 研究子任务可以独立验收，且共享项目状态已经稳定；
5. 有足够时间和调用成本比较 A/B/C，而不是只展示一次成功演示。

## 7. 对产品结构的影响

画布和看板不需要显示底层究竟是一个模型、一个 Agent 还是多个 Agent。用户看到的是任务目标、当前动作、来源、费用/时间提示、结果和需人工决定的事项。

因此首版对象模型保持稳定：

```text
画布发现缺口
→ 生成研究任务
→ 由 Workflow / 单 Agent / Multi-Agent 之一执行
→ 材料与证据入库
→ 更新受影响的发现与选项
→ 人工审核
```

执行方式属于任务运行策略，不应反过来控制咨询分析框架。
