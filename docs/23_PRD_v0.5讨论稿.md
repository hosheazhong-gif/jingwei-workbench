## 2. Loop engineering 对经纬意味着什么

Loop engineering 不是「让 Agent 自己写代码到停」。它是：你不再每一步手打下一句提示，而是设计外圈循环：

```text
触发 → 装入本项目状态 → 模型干活 → 另一个检查（不是自己打分）→ 写回账本 → 直到可验证的停止条件
```

对照当前失败：

| 外圈步骤 | 当前产品 | v0.5 应变成 |
|---|---|---|
| 触发 | 人在四个页面之间找按钮 | 打开一题，或补了一份材料，或点「写这一节」 |
| 装入状态 | 模型几乎看不到「下一步该回答哪条问题」 | 每次只带：本轮问题进度、当前稿、已有材料 |
| 干活 | 先拟到侧栏，空白题还会复述占位句 | 模型直接改稿上的一节，人在稿里收下或改 |
| 检查 | 核验七态、过不过、决策门（人当填表员） | 机械检查：无来源的数字标出来；停下条件不是模型自称写完 |
| 写回 | 候选和正文两套，人找不到「用这版」 | 同一篇稿的版本；来源仍不覆盖 |
| 停止 | 看不见进度 | 本轮问题是否够用、这一节是否已有稿、能否导出 Word |

人仍然做产品判断（这段能不能给经理看）。机器做「有没有来源 / 有没有新版本 / 测试过没」。这就是 maker-checker：写稿的模型不得给自己打满分。

明确不做：无人值守搜索循环、Multi-Agent 咨询剧场、把经纬做成 Claude Code 的 `/loop`。

## 4. 建议写入 v0.5 的产品定义

### 4.1 一句话

帮助一名顾问，在材料不全时，在**一块工作台**里看见本轮要回答的问题、让模型加快写出给经理的稿、材料始终在手边；系统不把没来源的数字装成已核实，也不覆盖旧材料。

### 4.2 默认界面（替换 v0.4 §10.1）

一块台面，三件事同时在：

1. **本轮问题**（进度）：每条是「还没写 / 草稿 / 我这轮够用了」。由人点，不是核验状态机。
2. **本轮稿**（中间）：就是以后导出的 Word。模型写的是这里的一节，收下后才算进稿。
3. **材料匣**（旁边）：文件和链接。没打开的网页不能当依据。

废弃作为默认导航：内部稿审查侧栏、本题/材料/内部稿四步跳转、过不过、核验七态、决策门状态栏。

旧审查面可以留成「技术详情」，默认不打开。

### 4.3 模型在圈里怎么转

```text
人选定一节（或一条本轮问题）
→ 系统装入：问题、现稿、已有摘录
→ 模型写出这一节候选
→ 机械检查：出现的数字/机构若无来源则标「未挂来源」
→ 人收下、改完收下、或丢掉
→ 进度随人点「这轮够用了」
→ 导出 Word
```

空白题不再用「系统不会代写」的占位句堵死模型。没有材料时，模型可以写**缺口稿**（还缺什么、客户口头怎么带归属写），不能发明统计数字。

### 4.4 内核不动

- `Source → EvidenceExcerpt → Claim → Finding/Option → DeliverableBlock`
- 新材料新 Source，不覆盖旧哈希
- 客户提供 ≠ 外部核实；宏观不单独证明项目需求
- 视图读同一对象 ID
- P-001仍是第一题，不是第二业务

### 4.5 仍然不做

画布、看板、知识库、搜索 Agent、券商/机场、精装 PPT、把核验枚举做回主按钮。

## 5. 建议的开发切片（通过 v0.5 之后才写代码）

1. 把本讨论收成 PRD v0.5，并改 cursor 规则里的默认界面句。  
2. 新工作台投影：一页三栏，读现有对象。审查页停止加功能。  
3. 「写这一节」：模型写入候选，人在稿里收下；沿用 revision，不新造第二套正文。  
4. 进度只显示本轮问题。核验退出主路径。  
5. 你用P-001样本 + 一个空白题走一遍。看不清进度或模型仍不加快，就停。

## 6. 请你拍板的四问

1. 进度是否就用「本轮问题：还没写 / 草稿 / 这轮够用了」，不要核验芯片？  
2. 模型写进稿，是否接受「无来源数字标红，但仍可收下」——人自己判断？  
3. 「内部稿」三字是否改成「本轮稿」或「给经理的稿」，避免再当产品壳？  
4. 旧审查侧栏是藏起来，还是这一版直接不进默认导航？
