# PRD v0.2｜经纬：策略与转型项目工作台

> 历史版本：本版以官方 JD 反推真实顾问任务，替代过于泛化的 v0.1；本文件继续保留完整愿景和行业研究。当前产品与 MVP 基线请使用 [PRD v0.4](01_PRD_v0.4.md)。

## 1. 精确产品定位

经纬服务于咨询售前和正式项目中的 Analyst / Associate / Consultant。即使输入只有客户的一句话和一个场地位置，也帮助顾问先形成有依据的初步理解、机会假设、研究方法和提案初稿；项目启动后，再继续支持研究、访谈、数据分析、诊断、选项、business case、路线图、PPT 和质检。

经纬不是：

- 万能咨询聊天机器人；
- 自动生成行业报告的七层 Prompt；
- ERP、数据平台或软件开发工具；
- 自动替客户决定战略；
- 用 AI 拼出一份无法追溯的百页 PPT。

## 2. 首批目标岗位

| 岗位 | 经纬覆盖 | 不覆盖 |
|---|---|---|
| Generalist / Strategy Analyst | 研究、问题树、分析、建议、PPT | 最终客户承诺 |
| Strategy & Transformation Consultant | 诊断、运营模式、business case、roadmap、PMO | 大型实施平台本身 |
| Digital Strategy Consultant | 数字成熟度、用例、需求、价值和路线图 | 详细系统架构和代码开发 |
| Real Estate / Industry Strategy Consultant | 产业、市场、空间、定位和实施 | CAD/BIM 专业设计 |
| Data/Research Analyst | 资料、数据、模型、图表和洞察 | 高级生产级数据工程 |

## 3. 产品导航不再采用七层

### 3.1 固定导航：顾问的工作对象

1. **Brief & Workplan**：任务、决策、问题树、假设、模块、负责人；
2. **Evidence & Interviews**：来源、文件、访谈、摘录、证据冲突；
3. **Analysis Studio**：数据表、benchmark、模型、流程、空间和图表；
4. **Diagnosis & Options**：痛点、根因、洞察、反证、选项和评分；
5. **Business Case**：价值、成本、资源、情景、风险和敏感性；
6. **Target State & Roadmap**：定位/目标状态、能力、举措、依赖、负责人和 KPI；
7. **Storyline & Deliverables**：故事线、PPT、Excel、memo、workshop；
8. **Review & PMO**：批注、版本影响、SteerCo、风险、进度和价值追踪。

### 3.2 可替换的项目模板

- 产业/行业战略；
- 区域/园区/地产策略；
- 增长与市场进入；
- 数字化转型；
- 运营模式与成本转型；
- 商业战略与定价；
- 商业尽调；
- 市场监测和月报。

模板决定 Analysis Studio 里出现什么分析组件，不改变整个项目的工作链。

### 3.3 两种工作模式

#### 售前探索模式（默认允许信息极少）

典型输入只有：客户的一句话、项目/场地名称、位置、零散背景或旧材料。

系统不要求用户先补齐全部数据，也不把缺数据当报错。它先用公开资料、地图/POI、相似案例和合理代理变量形成：

- 已知事实；
- 明示假设；
- 初步机会假设；
- 关键未知项；
- 建议的项目方法、访谈和数据请求；
- 可用于客户首次沟通的 proposal storyline。

此模式的目标是证明“我们理解了问题并知道怎样把它做清楚”，不是假装已经得到最终战略答案。

#### 正式项目模式

客户开始提供文件、数据和访谈机会后，将售前假设转成可验证的问题树，补充内部证据、模型、方案、经济性和实施计划。售前阶段的每个假设都必须保留状态：已证实、被推翻、仍待验证。

## 4. 十个核心功能模块

### F1｜Brief 解析与任务澄清

**输入**：客户邮件、会议纪要、RFP、任务说明、旧项目 PPT。  
**处理**：提取客户问题、最终决策、范围、交付物、时间、受众、限制和歧义。  
**输出**：一页 engagement brief + clarification questions。  
**信息不足时**：不阻断研究；用最小必要假设启动公开资料探索，同时把会改变方向的问题列为“客户待确认”。  
**人工门**：顾问确认系统对问题的理解、假设和对外措辞后，才生成客户可见材料。

### F2｜问题树、假设与 Workplan

**功能**：

- 按决策生成 issue tree；
- 每个问题绑定假设、分析、证据需求、负责人和截止时间；
- 检查重复、遗漏和“无法改变决策的问题”；
- 生成模块计划和每日/每周工作清单；
- 支持内审后重排优先级。

**交付**：issue tree、hypothesis tracker、workstream plan。

### F3｜研究与证据室

**功能**：

- 网页、PDF、PPT、Word、Excel 的检索和摘录；
- 每条证据记录来源、页码/单元格、日期、区域、单位和口径；
- 区分事实、来源观点、访谈观点、模型结果和顾问推断；
- 检测冲突数据、过期数据和单一来源依赖；
- 证据可以直接被某个假设、图表或 PPT 页面引用。

售前模式额外要求：

- 将公开数据、代理指标、案例类比和用户提供事实分开；
- 没有可靠数据时输出区间、计算逻辑或待验证项，不生成伪精确数字；
- “没有找到”不能写成“市场不存在”；
- 相似案例必须标明可迁移条件，不能以单个成功案例替代需求证明。

### F4｜访谈与工作坊

**功能**：

- 根据问题树生成访谈提纲；
- 对访谈纪要按问题、观点、证据、分歧和待办编码；
- 生成 stakeholder map；
- 设计 workshop agenda、pre-read 和选择题；
- 会后记录 decision、owner、open question 和 follow-up。

这项功能是 v0.1 完全遗漏、但 JD 高频出现的核心工作。

### F5｜分析工作台

共同组件：

- 数据清洗与字段字典；
- benchmark 和差距分析；
- 市场规模、份额和增长；
- 客户分群、旅程和漏斗；
- 价值链、生态和利润池；
- process map 与 pain point；
- maturity / capability heatmap；
- GIS、区位和空间分析；
- 情景和敏感性；
- 图表与数字 QA。

所有模型保存输入、公式、假设、输出和版本，不允许只保存 AI 的文字解释。

### F6｜现状诊断与根因

**输出对象**：

- observation：观察到的事实；
- implication：这意味着什么；
- root cause：为什么发生；
- evidence for / against：支持与反证；
- confidence：置信度；
- open question：仍需验证什么。

数字化项目还生成 as-is journey/process、system/data/capability gap；地产项目生成供需、空间、客流、产品和运营约束。

### F7｜选项与 Business Case

**功能**：

- 生成至少两个可比较选项，不直接只给一个答案；
- 使用客户确认的价值、可行性、风险、能力和时间标准；
- 建立收益、成本、资源、投资和时间模型；
- 支持 downside/base/upside；
- 标记硬收益、软收益和待验证收益；
- 输出 recommendation rationale 和 no-go conditions。

### F8｜目标状态与路线图

地产/产业模板：定位、产业/业态组合、空间/功能、招商/运营主体。  
数字化模板：future journey/process、target operating model、业务需求、数据/技术能力和治理。  
共同输出：initiative cards、依赖、波次、负责人、里程碑、KPI、风险和决策门。

### F9｜故事线与交付物

**支持的中间交付**：

- fact pack；
- interview synthesis；
- analysis pack；
- module update；
- workshop pre-read；
- SteerCo update；
- decision memo；
- client deck storyline；
- Excel appendix。

先生成页面目的、核心信息、证据和建议图表，再生成页面内容，避免“先写 50 页再找逻辑”。

### F10｜Review、QA 与 PMO

**自动检查**：

- 无来源数字；
- 同一指标跨页面不一致；
- 来源时间/区域/单位错配；
- 结论强于证据；
- 图表和正文数字不一致；
- 建议缺少 owner、value、risk 或 next step；
- 修改数据后失效的下游页面。

**PMO**：status、milestone、RAID、decision log、benefit tracking、SteerCo update。

## 5. 首批完整工作流

### W0｜一句话到售前初案

```text
一句话需求 + 场地位置
→ 识别客户可能要做的决定
→ 已知 / 假设 / 未知三栏
→ 公开信息与区位初查
→ 竞品、案例、产业/客户线索
→ 2—4 个机会假设及反证
→ 建议的方法、数据请求和访谈计划
→ 售前 proposal 初稿
```

建议的售前交付结构：

1. 我们对客户问题和目标的理解；
2. 基于公开信息的初步观察；
3. 需要进一步验证的机会假设；
4. 拟采用的研究与分析方法；
5. 数据请求、访谈对象和现场工作；
6. 项目阶段、交付物和下一步。

禁止在此阶段把机会假设包装成确定建议，也不应在缺少面积、租金、成本、客户需求等数据时制作伪精确 business case。

### W1｜产业/地产策略：保留经纬主线

```text
项目决策
→ 产业/市场边界
→ 需求、客户与场景
→ 竞争、案例、价值链与政策
→ 区位、空间和项目能力
→ 定位/产业/业态选项
→ 面积/经济性/风险
→ 招商、运营和实施路线图
→ 策略方案
```

原七层被吸收，但不再逐层生成长文。

### W2｜数字化转型：候选模板，暂不进入 MVP

```text
业务价值目标
→ 行业数字趋势和 competitor benchmark
→ 客户旅程/流程/系统/数据/组织现状
→ 痛点、成熟度和能力差距
→ 数字/AI/自动化用例池
→ 价值-可行性-风险优先级
→ target operating model + requirements
→ business case
→ transformation roadmap + PMO + change
```

这条流程可以对应部分咨询公司的数字化/转型岗位，但目前没有证据证明它是用户首要场景，因此仅保留为研究样例，不作为开发优先级。

## 6. 一个具体售前示例

### 客户问题

“华南某镇一处冷链仓大部分已由某仓储会员店使用，剩余约三分之一空间应该做什么？”

### 经纬中的过程

1. 只记录已知事实：位置、现有用途、某仓储会员店使用大部分空间、剩余约三分之一；
2. 明示暂定目标：降低空置并提高剩余空间的可持续收益，待客户确认；
3. 外部初查：交通、周边食品与商贸产业、冷链项目、政策、潜在客户和相似案例；
4. 形成假设：继续冷链招租、食品加工/中央厨房、城市配送、交易选品或混合使用；
5. 每个假设列支持证据、反证、场地要求和待验证问题；
6. 不虚构面积、租金、能耗和改造成本，先列客户数据请求；
7. 输出首次沟通材料：初步观察 + 机会假设 + 项目方法 + 数据/访谈计划 + 交付范围。

## 7. MVP 的真实范围

第一版不同时实现八种模板。开发顺序：

1. W0：用“一句话 + 场地位置”生成可审查的售前初案；
2. 共用底座：Brief、假设、证据、竞品/案例、分析、storyline 和 QA；
3. W1：客户补充资料后，将同一项目推进为产业/地产策略正式分析；
4. 验证售前假设能否无损转入正式项目，而不是重新做一遍；
5. 再决定是否加入市场进入、数字化或运营模式模板。

## 8. 对求职作品集的验收

一个可展示的经纬项目必须包含：

- 原始 client brief（使用公开/合成案例并明确标识）；
- issue tree 和 workplan；
- source ledger 和 interview plan；
- 至少一个可复算模型；
- as-is diagnosis；
- 选项和 business case；
- target state / roadmap；
- 10—15 页以内的 management storyline；
- QA 报告；
- 说明哪些由本人判断、哪些由 AI 辅助。

这样才能对应咨询 JD，而不只是展示一个漂亮的 AI 页面。

## 9. 求职训练能力：研究附录，不进入 MVP

Case 与真实项目共享问题定义、结构化分析、商业计算和综合建议等能力，但它不是同一个产品场景：

- 项目工作台服务顾问交付，AI 应主动协助搜索、分析、生成和质检；
- Case 训练服务求职者评估，AI 需要隐藏答案、控制信息释放并记录评分；
- 两者的用户、交互逻辑、数据权限、成功指标和诚信边界都不同。

因此，完整 Case Lab 暂不纳入经纬 MVP，也不作为证明产品价值的必要条件。当前仅保留两项低成本兼容设计：

1. 项目对象的数据结构允许未来将公开或合成项目导出为脱敏练习材料；
2. 求职作品集可展示问题树、证据链、模型、建议和复盘，证明用户具备 case 所考察的底层能力。

只有在 W0 售前初案与 W1 产业/地产策略真实工作流跑通后，才重新评估 Case Lab。届时优先考虑独立模块，而不是污染核心项目界面。研究资料见 [Case 面试、在线训练与真实工作的关系](06_Case面试与训练模式.md)。

## 10. 判断与证据原则

经纬的 AI 不以“顺从用户”为目标，而以提高决策质量为目标。所有重要输出遵守 [协作与判断协议](07_协作与判断协议.md)：先检查前提和信息缺口，区分事实、推断、假设与观点；对数字、人物和关键结论尽量核实；必要时直接提出异议，并列明依据、风险、替代解释和遗漏变量。
