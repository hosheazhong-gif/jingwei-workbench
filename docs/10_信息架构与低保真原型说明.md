# 经纬信息架构与低保真原型说明

> 状态：后续个人工作台愿景原型；不作为 PRD v0.4 的 P0 实现范围  
> 日期：2026-08-12  
> 目标：保留并验证工作台方向，避免把现有三视图误当成首个 MVP 的全部功能。

## 0. 与当前 MVP 的关系

这份原型仍然有价值，但它描述的是经纬从“单人研究闭环”扩展到“个人咨询工作台”后的形态。四工作区方案经过测试后不再作为 PRD v0.4 的 P0 默认界面；当前默认入口是“内部稿 + 来源与主张审查侧栏”。底层仍保留同一条对象链：

```text
Brief / ResearchQuestion
→ Source / EvidenceExcerpt / Claim
→ Finding / Option
→ Draft / Review / Override
```

当前原型中的咨询项目画布、研究执行看板、四工作区深度视图和完整交付故事线均归入后续验证假设。团队成员、负责人、权限和跨人任务协作归入更后阶段。P0 只在报告段落需要判断时投影相关对象，不提前建设多套完整视图。

## 1. 信息架构原则

经纬采用三种视图，而不是在“咨询分析工具”和“项目看板”之间二选一：

1. **咨询项目画布（决策层）**：围绕客户决策组织问题、诊断、证据、选项和可行性，是产品的核心视图；
2. **研究执行看板（协作层）**：管理工作包、负责人、状态、截止时间、阻塞和补料，是团队推进项目的执行视图；
3. **交付故事线（表达层）**：将已确认的发现和建议投影成备忘录、PPT 页面与汇报顺序，是对内/对客表达视图。

三种视图共享同一组底层对象。画布中的研究缺口可以生成看板任务；看板完成后产生的证据和发现回到画布；画布中被批准的内容才能进入交付故事线。系统不得让用户在三处重复录入或手工同步同一结论。

产品导航围绕顾问要管理的对象，而不是模型能力或固定七层：

1. **项目概览**：当前问题、范围、阶段、风险和最近变化；
2. **任务与假设**：委托原话、决策问题、已知/假设/未知、研究优先级；
3. **研究工作包**：本体、区位、产业需求、产业链、政策、案例、可行性等并行模块，数据能力嵌入各模块；
4. **证据台账**：网页、文件、摘录、口径、冲突、核验和排除记录；
5. **选项与可行性**：候选方向、机制、反证、前提与最小验证动作；
6. **交付与评审**：报告/PPT 内容块、引用、批注、批准/否决和版本。

聊天可以作为新增任务、追问和修改的入口，但不是产品的唯一界面，也不是项目状态的唯一载体。

## 2. 决策主线与研究执行的关系

### 2.1 推荐分析主线

咨询项目画布默认按照认知和决策逻辑从上到下组织：

```text
0. 决策定义
→ 1. 项目本体诊断
→ 2. 区位与市场环境
→ 3. 产业与需求
→ 4. 客群、生态与产业链
→ 5. 政策与案例验证
→ 6. 策略选项
→ 7. 可行性与优先级
```

该顺序用于帮助顾问理解问题和检查逻辑是否闭合，不代表实际研究必须按顺序完成。政策、案例、本体、区位等研究可以并行、跳转和返工。

### 2.2 数据分析的位置

数据分析不作为一个固定业务工作包，而是贯穿各分析层的共用能力：项目本体使用租赁、面积和租户数据；区位市场使用供需、租金和竞品数据；产业研究使用市场和企业数据；可行性使用成本、收益和情景数据。

没有足够数据时，系统应生成数据缺口和最小验证动作；有数据时，系统检查来源、单位、时间、实际/预测、公式和口径闭合。市场规模数据只能支持行业背景，不能单独证明某个项目存在需求。

## 3. 后续工作台首屏选择

早期P-001低保真页面曾选择“研究工作包”，因为它同时验证三个关键判断：

- 区位、产业链、政策、案例等是并行模块，而不是七个步骤；
- 每个工作包可以停在“暂时够用”“待补数据”“受质疑”等不同状态；
- 新材料进入后，系统提示影响范围，而不是直接覆盖旧结论或重新生成全部报告。

页面由五部分组成：

```text
项目标题与补料入口
→ 三档决策门
→ 当前决策问题与已知/未知
→ 左侧并行工作包 + 右侧工作包详情
→ 新材料影响提示
```

第一版原型先展示“研究执行看板”，用于验证并行、补料和影响追踪。第二版已将咨询项目画布设为默认首屏，并保留“执行看板”和“交付故事线”作为可切换视图。这些结果是 P1 的设计输入，不要求 P0 照此实现。

画布按 0—7 分析主线展示当前判断、证据/反证、信息缺口和下一研究任务；从画布进入看板时保留任务所属分析层及建议执行方式。执行方式可以是固定 Workflow、单 Agent、Multi-Agent 对照实验或人工判断，但不改变画布结构。

## 4. 关键交互

### 4.1 切换工作包

用户点击任一工作包，可查看：研究问题、当前发现、支持与反证、缺口、证据数量和下一最小动作。切换模块不会改变其他工作包状态。

### 4.2 补充材料

用户选择材料类型并加入收件箱。系统先保存材料，不直接把内容升级为结论；解析后提示它可能影响哪些证据、发现、选项和交付页面。

### 4.3 处理受影响内容

用户可逐项确认：保留旧结论、更新、降级为待验证、或标记冲突。只有经确认的变化进入新的内部评审版本。

### 4.4 决策门

项目不显示虚假的统一完成百分比，使用三个可解释状态：

1. 可继续头脑风暴；
2. 可供内部评审；
3. 可用于售前沟通。

决策门依据关键对象是否达到最低质量，而不是要求全部研究工作包完成。

授权用户可以选择“带风险推进”跨过决策门。界面必须让用户选择按假设推进、从本版排除或以区间/情景表达，并在交付故事线中保留显著限制。推进不会把未核验证据改成已核实事实。

所有搜索内容进入画布前先作为候选材料。模型训练记忆若无法定位可核验来源，只显示为“模型先验/未核验线索”，不能生成引用或支撑事实性页面。

## 5. 原型中的P-001状态

| 工作包 | 示例状态 | 原因 |
|---|---|---|
| 项目本体与运营 | 暂时够用 | 已有空置、设施和客群判断，但缺租赁台账与设施参数 |
| 区位、市场与竞争 | 待补数据 | 有交通与区域竞争线索，口径尚未统一 |
| 客群与产业链 | 进行中 | 已形成中游集中、上下游不足的假设，需求尚未访谈 |
| 政策 | 待补数据 | 有政策方向，缺官方条款与项目适用性核对 |
| 案例与竞品 | 暂时够用 | 已支持方向发散与筛选，尚不能证明项目需求 |
| 选项与可行性 | 未开始 | 尚缺空间、需求、经济性和运营数据，不应伪精确评分 |

数据表不再单独形成一个业务工作包。其质检问题显示在“产业与需求”的证据状态中；租赁台账等项目数据则显示在“项目本体诊断”中。

## 6. P1 工作台可用性测试

让用户以“经理临时发来一份新的租户与空置面积 Excel”为情景，完成：

1. 找到补充材料入口；
2. 判断材料应关联哪些工作包；
3. 查看系统识别的受影响结论；
4. 将一条旧发现降级为待验证；
5. 确认当前是否仍达到“可供内部评审”；
6. 找到下一最小研究动作。

观察用户是否理解工作包状态、影响提示和决策门，不以视觉精美或生成速度作为本轮成功标准。

## 7. 本轮不设计

- 完整登录、组织和权限管理；
- 自动生成精装 PPT；
- GIS、复杂财务模型和付费数据库连接；
- 多 Agent 运行监控；
- 项目管理甘特图、工时和收费管理；
- 面试 Case 训练入口。

## 8. 进入本原型下一轮前的门槛

1. 先按 PRD v0.4 用P-001材料跑通一次最小研究闭环；
2. 验证结构化状态确实减少了引用错误、补料返工或上下文恢复成本；
3. 观察用户是否需要跨多个研究工作包持续回到项目；
4. 只有前三项成立，再评审画布的分析层、措辞、信息密度和视图切换；
5. 随后才补画完整证据台账、选项与可行性、执行看板和交付故事线。

## 9. 后续问题拆解与诊断设计假设

未来个人工作台可以验证一项可组合能力，而不是新增固定模式：

```text
原始问题
→ 明确真正要解决的决策问题
→ 还原涉及的业务流程
→ 找到流程卡点和可能成因
→ 用逻辑树或专业框架拆分析维度
→ 形成候选度量与指标
→ 用材料、数据和访谈验证
→ 由人确认适合当前项目的指标体系
```

系统负责辅助拆解、提出候选项、保存逻辑关系和提示验证缺口；人负责确认问题定义、因果判断和最终指标。该能力未来通过 `AnalysisModule`、`AnalysisArtifact` 和 `ViewProjection` 接入，不能把某一套流程、逻辑树或指标库写死在核心 schema 中。

分类：**后续验证假设**。它不与当前对象模型冲突，但不进入P-001 P0、当前页面或本轮验收。
