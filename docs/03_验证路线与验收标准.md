# 验证路线与验收标准

## 1. 为什么先验证而不是直接开发全平台

当前最大风险不是模型选错，而是把想象中的咨询流程产品化。公开岗位信息能证明共性，但只有真实任务能验证：顾问如何收到需求、在哪里发生返工、哪些判断可以结构化、什么输出真正进入讨论。

因此首轮只用P-001 冷链园区测试完整闭环。券商降本增效作为第二个迁移测试，用来判断同一对象模型能否服务非地产专题研究，而不是同时定义首版功能。产业园月报、产业策划和机场商业保留为后续回归案例。

## 2. 五个参考工作流

### Case 0：一句话 + 场地位置的售前任务

验证：

- 在没有内部数据时能否启动，而不是要求用户先填完整表单；
- 能否区分公开事实、代理指标、类比案例、假设和未知项；
- 能否形成有针对性的客户澄清问题、数据请求和访谈计划；
- 能否提出多个可验证机会假设，而不是伪装成最终建议；
- 能否生成用于首次沟通的 proposal storyline；
- 项目启动后，售前假设和证据能否直接转入正式工作流。

这是最贴近用户原始痛点的探索型 MVP 候选：在信息极少的情况下，较快产出一份能够与 senior 或客户继续讨论的初版材料。

P-001 冷链园区的历史材料显示，这类任务不是固定顺序的一次生成，而是“现场观察/一句话任务 → 多个研究工作包 → 讨论改变假设 → 新一轮案例与数据 → 综合诊断与方向筛选”。区位、本体、产业链、政策、案例和数据应并行存在，并允许任一工作包暂停、补料和重开。

### Case 1：券商降本增效——搜索与人工材料混合研究

验证：

- 能否先定义“头部”“降本增效”、公司范围和时间范围；
- 公开搜索与用户上传材料能否进入同一材料收件箱；
- 能否找到公司公告、年报或原始案例，而不是停在转载摘要；
- 能否区分公司已披露动作、第三方报道、供应商宣传和顾问推断；
- 用户中途补料后，旧证据、发现和报告大纲能否连续更新；
- 能否生成带来源、适用条件和待核实项的内部研究稿。

### Case A：产业园市场月报——后续重复型研究回归

验证：

- 多源采集与字段标准化；
- 固定口径、时效和区域/月度比较；
- 变化识别与趋势解释；
- 证据到月报页面的追溯；
- 更新一个数据后下游页面是否同步提示。

这是后续重要回归工作流，因为输入输出稳定、容易定义正确答案；但它不再与低信息售前争夺首个 MVP 优先级。

### Case B：产业/园区前期策划——探索型策略工作

验证：

- 模糊任务转问题树；
- 产业、政策、案例、本地条件和机会的组合；
- 从资料摘要到策略选项的跃迁；
- 反证、信息缺口、经济性和实施条件。

### Case C：机场商业——数据、空间与策略混合工作

验证：

- 多表口径闭合与版本差异；
- 旅客旅程、空间分区、业态和品牌的连接；
- 情景与敏感性；
- Excel、平面分析、图表和 PPT 共用事实底盘。

机场案例中的历史事实与 2026 合成增强结果必须继续分开。

## 3. 首个可运行版本的完成标准

用 Case 0 P-001 冷链园区售前作为唯一首轮基准，系统需要做到：

1. 只输入一句问题时也能形成可编辑的任务理解卡；
2. 只生成本轮必要的 ResearchQuestion，而不是强制完整问题树；
3. 将公开网页和人工文件统一保存为 Source，保存项目快照、哈希和可访问状态，并形成可定位的 EvidenceExcerpt；
4. 把关键事实拆成原子 Claim，区分事实主张、推断、假设、顾问判断和 ModelSuggestion；
5. 自动提示缺字段、重复记录、口径冲突和异常变化；
6. 形成带替代解释、反证和缺口的 Finding；
7. 输出一版可编辑的内部研究初稿和 PPT 页面大纲；
8. 任一关键事实性内容可追溯到 Claim、EvidenceExcerpt 和 Source；
9. 顾问可以批准、修改、否决或带风险推进并记录原因；
10. 修改来源、新增材料或来源路径失效后，系统能指出显式链上受影响的 Claim 和初稿段落；
11. 不要求用户重复维护画布、看板和故事线中的同一内容；
12. 不泄露客户名称、个人信息、报价或未授权数据。

附加的数据质检要求：图表数字必须记录单位、时间、地域、实际/预测和来源；增长率与规模序列不闭合、只有硬编码值或缺少公式时必须提示人工核验。

## 4. 对比实验

同一任务分别采用：

- 原人工流程；
- 普通大模型聊天；
- 经纬结构化工作流。

记录：

- 启动到第一版问题树时间；
- 搜索、复制、清洗、核对、写结论和排页面分别耗时；
- 引用缺失、数字错误和返工次数；
- 哪些 AI 建议被接受、修改或否决；
- 顾问主观上最有价值和最干扰的步骤。

只有当经纬在可追溯性、错误率或返工上有明确改善，才继续扩展模板。

同时记录产品行为而不只记录功能是否运行：

- 用户是否愿意在第二个真实任务继续使用；
- 用户是否为了完成结构化字段而增加额外负担；
- 输出进入 Word/PPT 后是否仍需大面积重做；
- 经理是否真正使用来源状态、反证和信息缺口，而不是忽略这些内容。

出现以下情况时停止扩平台并考虑转向：

- 结构化维护成本超过减少的返工；
- 用户只生成一次便离开，不再回到项目；
- 相比普通 AI 没有减少关键事实错误或上下文恢复成本；
- 真正有价值的只有文件问答、资料摘要或报告生成。

## 5. 产品发现问题清单

每复盘一个真实任务，只问可还原流程的问题：

1. 领导/客户最初的原话是什么？
2. 最后要做出的决定和交付物是什么？
3. 你先打开了哪些旧文件、网站和模板？
4. 哪些字段或分析口径是固定的？
5. 哪一步最耗时，哪一步最容易返工？
6. 哪些判断必须问领导，哪些你可以自己决定？
7. 内审最常改数据、逻辑、措辞还是版式？
8. 什么情况代表这一页或这个模块“可以交了”？
