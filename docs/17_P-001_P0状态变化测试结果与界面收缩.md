# P-001 P0 状态变化测试结果与界面收缩

> 后续状态：本文件记录四工作区 v0.3 当时的失败结论；报告优先审查方案随后已通过本轮理解门槛，见 [报告优先审查原型测试结论](18_报告优先审查原型测试结论.md)。

> 日期：2026-08-12  
> 测试对象：P-001 P0 原型 v0.3  
> 结论：未通过；触发既有“报告中的来源与主张审查侧栏”收缩假设

## 1. 测试回答

1. 新材料加入后的重审范围被回答为“宏观市场规模、综合判断方向”。测试者感知到了宏观层和判断层会受影响，但没有稳定区分受影响的判断与具体报告段落。
2. 对新文件为何不能直接写数字的回答是“已有初稿，加入新文件也不能确定是正确的”。测试者理解不能自动相信新材料，但未明确说出可访问性与来源、实际/预测、单位、时间、公式核验的区别。
3. 对带风险推进的理解是“改变内部稿对应部分，不改变工作流大方向”。这没有命中核心规则：改变当前版本对相关内容的处理，不改变材料或主张的核验状态。
4. 测试者无法明确说出普通聊天下需要自行恢复和重查的事项，并表示自己也有些不确定。
5. 未形成“返工收益值得维护成本”的明确判断。

## 2. 第一性原理判断

本轮失败不是因为缺少更多功能，而是产品让用户先理解了系统对象和状态，再完成本来属于“修改报告”的任务。用户真实目标是判断一段文字现在能否写、为什么、补料后哪里需要改；Source、Claim、OverrideDecision 应当作为底层记录，而不是要求用户先掌握的操作语言。

继续增加工作区、状态标签或解释文案会进一步提高当下认知成本，尚无证据能换来更大的返工收益。因此当前不能进入完整技术架构，也不应继续扩四工作区原型。

## 3. 强制分类

### P0 必需修正

- 将下一轮界面收缩为“内部稿为主、来源与主张审查侧栏为辅”；
- 风险推进改为作用于当前段落的自然语言动作，底层仍生成 OverrideDecision；
- 补料后直接提示受影响的判断与报告段落，不要求用户先进入 Source/Claim 工作区；
- 继续保留底层 Source—EvidenceExcerpt—Claim—Finding—DeliverableBlock 主链，不因界面收缩复制状态。

### 后续验证假设

- 如果报告优先界面能让用户说清楚“现在能否写、为何、补料影响哪里”，再验证是否需要独立研究工作区；
- 完整四工作区可能只适合复杂项目深度视图，而不是 P0 默认入口。

### 不做

- 不增加券商、机场、轻量研究入口、完整工作台、Agent 或更多状态对象。

## 4. 下一对照原型

报告优先审查原型位于：

`<本机原型目录>/case-p001-report-review.html`

它不删除底层对象，只把操作入口改为：

```text
内部稿段落
→ 查看“现在能否写、为什么、来自哪里”
→ 在当前段落处理资料不足
→ 新材料加入后直接显示受影响的判断与段落
→ 局部重审
```

下一轮只比较它是否比四工作区原型更容易理解，不增加新业务能力。
